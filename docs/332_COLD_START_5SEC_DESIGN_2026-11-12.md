## 2. 5 秒に届くための結論

**画面が出た後に API を呼ぶ形のままでは、5 秒は物理的に届かない。**
アプリの枠まで 3.4〜3.8 秒 ＋ 冷えた API の最低 2.6 秒 ＝ **6〜6.4 秒**が下限（こちらの処理がゼロでも）。

→ **B（doGet にデータの完成品を埋め込む）が必須**。doGet は画面の HTML を返す実行そのもので、既に動いている。
ここでデータも一緒に返せば、**画面が出るまでの API の往復は 0 回**になり、5 秒の予算は「アプリの枠まで」とほぼ同じになる。

**予算（冷えた状態・推定）**

| 区間 | 今 | 目標 |
|---|---|---|
| doGet（サーバー） | 1.5〜2.0 秒（データなし） | 1.8〜2.4 秒（プロパティからデータを読む分 ＋0.3〜0.4） |
| 枠の表示まで（通信・iframe・JS の展開） | 3.4〜3.8 秒 | 3.6〜4.2 秒 |
| ダッシュボードの描画 | ＋19 秒（API 待ち） | **＋0.2〜0.5 秒（埋め込み済みのデータで描くだけ）** |
| **合計** | **23 秒** | **約 4〜4.7 秒** |

余裕は 0.3〜1 秒しかない。§4 の「枠を速くする」で余裕を作る。

## 3. 設計の柱

### 柱 1: 完成品はすべて「消えないプロパティ」に置き、裏で作り直す（データを温める）

| 完成品 | 大きさ | 今 | これから |
|---|---|---|---|
| 管理者認証（`docs/328`） | 約 1.2 KB | プロパティ・最大 5 分 | プロパティ・**権限名を含める**・最大経過時間を延ばす（§6 D1） |
| 設定（マスタの選択肢を含む） | 約 18.5 KB | キャッシュ 5 分 | **プロパティ**（3 分割） |
| マスタ（34 表） | 未計測（設定の中にも入る） | キャッシュ 10 分 | **プロパティ**。作るときは **REST `batchGet` 1 回**（34 表を 1 回の通信で） |
| ダッシュボード | 約 116 KB | キャッシュ 10 分 | **プロパティ**（約 13 分割）。中身を計って、最初の描画に要らないものを外す（§4-3） |
| ロール一覧 | 小 | キャッシュ 5 分 | 認証の完成品に入れる |
| 未処理件数 | 数 | 毎回数える | ダッシュボードの完成品と一緒に作る |
| 公開ポータルの設定・研修一覧 | 約 9 KB＋研修 | キャッシュ 10 分（設定） | **公開プロジェクトのプロパティ**（operator 提案「完成品を裏で作って渡す」） |

**作り直す時機（3 つの経路）**
1. **時間トリガーで約 10 分ごと**（管理・公開の各プロジェクト）。冷えた状態で開いても、完成品は最大 10 分前のものが必ずある。
   ※ トリガーはスプレッドシートにも触れるので、DB も温まったままになる。
2. **書き込みの最下層で**（既にある `invalidateSettingsCache_`・`invalidateMasterOptionsCache_`・`clearAdminPermissionCaches_`）。軽いもの（認証・設定・マスタ）はその場で作り直し、重いもの（ダッシュボード）は「古い」の印を付ける。
3. **画面を出した後の裏の更新**（§3 柱 2）。

**守ること（`docs/325` §3.4 を実装に落とす）**
- 分割した完成品は**新しい世代を書き終えてから「現在の世代」を指す 1 件を替える**（書きかけを読まない）。古い世代は替えた後に消す。
- 合計の大きさ: 認証 1.2＋設定 18.5＋ダッシュボード 116 ≒ 136 KB。切り替えの間は 2 世代 ≒ 272 KB。上限 500 KB の内。**書く前に大きさを測り、400 KB を超えるなら保存せずに今の経路で答え、警告を出す**。
- **トリガーは HEAD のコード、web アプリは版のコードで動く**。開発中に push しただけの HEAD が、版と違う形の完成品を書くおそれがある
  → 完成品に**形式の番号**を入れ、読む側は自分の知らない番号なら使わない（今の経路で答える）。
- 完成品が無い・壊れている・形式が違う → **今の経路（API）で答える**。表示が遅くなるだけで、間違ったものは出さない。

### 柱 2: 古くても先に出し、裏で新しくする（stale-while-revalidate）
- doGet は完成品（最大 10 分前・書き込み直後は作り直し済み）を埋め込む。画面はそれで**すぐ描く**。
- 完成品が「古い」の印付き、または作ってから一定時間（例 2 分）を超えていれば、画面を出した後に **1 回だけ** API で最新を取り、差し替える。
- **認証は別**: 権限の判定に古いものは使わない。認証の完成品は今の鮮度の規則（`docs/328` §5）のまま。doGet でも同じ関数で確かめる。

### 柱 3: doGet で本人を確かめてから埋め込む（B）
- 管理は組織内公開なので、doGet でも `Session.getActiveUser()` で閲覧者が分かる（今の API と同じ）。
- **管理者でなければ、データは埋め込まない**（今と同じく、画面は 404 の表示）。権限ごとに絞る（ダッシュボードは `admin-settings` のメニューを許された人だけ、件数は `change-requests` だけ）。
- 埋め込む JSON は `<` を `<` に、U+2028・U+2029 も逃がす（`</script>` で HTML を壊されない）。
- 置き場所は今の `window.__DEEPLINK__` と同じ（`doGet` の先頭に差し込む `<script>`）→ `window.__ADMIN_BOOT__`。
- 画面: `__ADMIN_BOOT__` があれば、認証・初期データ・件数の呼び出しをしない。無ければ今の経路。
- ログイン成功の記録（0.4 秒）は doGet でしない。**表示の後に回す**（operator 了承済み 2026-11-12）。裏の更新の呼び出しで記録する。

### 柱 4: 重複と再試行をなくす
- 埋め込みがあれば、起動の API は 0 本 → 2 本が同じものを作り直す問題は消える。
- **自動再試行の 15 秒は、冷えた状態の呼び出しより短い**（18〜24 秒）ため、毎回同じ呼び出しを重ねていた。
  柱 1〜3 で呼び出し自体が速くなる（冷えても 3〜4 秒）ので、15 秒を超えるのは本当の通信の不調だけになる。
  あわせて、**再試行の前に、元の呼び出しの応答も受け付ける**（見切った呼び出しが後から返ったら使う）形にする（`src/shared/connectionRetry.ts`・3 画面共有）。

## 4. 枠（3.4〜3.8 秒）を速くして余裕を作る

1. **doGet のプロパティを 1 回で読む**: 今は `SCRIPT_ID_*` を 3 回に分けて読む（冷えた状態で 1 回 50〜90 ms）→ `getProperties()` 1 回で、完成品の全部と一緒に。
2. **doGet の内訳を計る**: `createHtmlOutputFromFile`（432 KB）・文字列の差し込み・`setFaviconUrl` などの時間を、計測の仕組みで取る（未計測）。
3. **ダッシュボードの完成品を小さくする**: 116 KB の中身を計り、最初の描画に要らないもの（一覧の全件など）は裏の更新で取る。
4. **JS を小さくする**: 管理の HTML 432 KB（圧縮後）。使う頻度の低い画面（名簿の設計・帳票・Excel など）を、**圧縮のまま同梱し、開いたときに初めて展開・評価する**（往復は増やさない）。起動ローダー 6 要素の契約（AGENTS L3.4）は守る。まず大きさの内訳を計る。

## 6. ご判断をいただくこと

**operator 決定（2026-11-12）: D1〜D3 は案のとおり（D1 認証の最大経過時間 1 時間・D2 時間トリガーを足す・D3 ダッシュボードは古くても先に出し裏で差し替え）。D4 は計ってから判断。**

| # | 事項 | 案 | 理由 |
|---|---|---|---|
| D1 | 認証の完成品の最大経過時間 | **5 分 → 1 時間** | 管理画面の変更は即時、直接編集も最終更新日時で約 2.5 分。延ばした上限が効くのは「最終更新日時が正しく変わらない」異常時だけ。確かめられないとき（Drive が読めない）は今どおり正本で作り直す |
| D2 | 時間トリガーを足す（管理・公開に「完成品の作り直し」約 10 分ごと） | 足す | 1 回 約 5〜8 秒 × 144 回 ≒ 1 日 12〜20 分。Workspace の上限は 1 日 6 時間（既存の定期処理の使用量は計画の最初に確かめる）。トリガーの設定は MASTER がエディタで実行（承認） |
| D3 | ダッシュボードは最初に最大 10 分前の内容で出し、裏で最新に差し替える | 許容する | 管理画面での書き込みは作り直すので即時。古くなるのは別のプロジェクト（公開の申込など）の変更だけで、表示の後に自動で直る |
| D4 | 使う頻度の低い画面の JS を開いたときに展開する | 計ってから判断 | 起動ローダーの契約に触れるので、効果を数字で確かめてから |
