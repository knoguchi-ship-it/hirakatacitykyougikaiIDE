2. 観点別・所見と修正案

A. リレーション整合性（信頼性）

構造的前提: Spreadsheet を DB とするため FK 制約・トランザクション・cascade が存在せず参照整合性はコード依存。repair* 関数の存在自体が過去の崩壊の証跡。

所見重大度修正案
cascade がほぼ未実装＝子レコードの広範な孤児化High (初版High→一次Med→精査で復帰)実体は会員/職員/認証/whitelist を in-place soft delete のみ。年会費/研修申込は snapshot だが live 無処理。役員/請求/振込口座/支払い/変更申請は完全放置＝真の孤児。a1 cascade アーカイブへ再設計（docs/249）
申込者参照の相互排他が宣言的でなく一部混在が未検出Med (訂正:初版High)実際は外部×職員混在・会員×職員不一致を検証済。会員+職員併存は正当。narrow ケースを宣言的制約＋test:er-sync で補強
申込者解決 legacy 関数の誤用余地（v376.12 実害源）High (緩和済)legacy に @deprecated、送信/名簿/本人解決は canonical 統一を grep gate 化、v377 で撤去

D. セキュリティ（5視点）

  • Critical: 0（docs/109 の3件は v261-263 で是正: deny-by-default / session principal override / PBKDF2+pepper）
  • High H1 パスワード KDF 強度: PBKDF2 1万反復 < OWASP 60万+。pepper で緩和中 → GCP Phase 0（Argon2id/Cloud Run）が根治
  • Med M1 XFrame ALLOWALL が3 split 共通（L889）→ member/admin は DENY に
  • Med M2 OAuth scope: member split に drive+cloud-platform が残存（裏取り済・削除候補）。cloud-platform は連携境界に限定
  • Med M3 v376.51 preview の client-only 書込ガード → 権限昇格なし（server は MASTER 不変）で実リスク低。server flag 突合で強化可
  • Low email 正規表現簡易 / webapp access 混在の手順化 / REDIRECT ログ宛先確認
準拠度: OWASP ASVS L1 PASS / L2 部分 / Top10:2021 主要 Compliant / NIST CSF・SSDF は Govern/Protect 良好、Detect(継続監視)・CI gate 自動化が運用確認待ち。
