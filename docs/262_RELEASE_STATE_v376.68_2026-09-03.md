## 2. 実装

管理ポータル → システム → **データ出力（CSV）**。テーブルを選んでボタン 1 つで CSV を取得する。

| 項目 | 内容 |
|---|---|
| 形式 | CSV（UTF-8 BOM 付き）。Excel でそのまま開ける |
| 対象 | 業務テーブル・マスタ（アーカイブを含む）。**認証テーブルとそのアーカイブを除く 56 件** |
| 削除済み行 | 既定は除外。チェックで含められる |
| 上限 | 1 回 20,000 行（実行時間の安全弁）。打ち切り時は画面に警告 |
| 権限 | menu `data-export`。**既定は MASTER のみ**。事務局へ渡す場合は MASTER が 権限管理 から明示付与 |

### 安全設計

| 対策 | 内容 |
|---|---|
| **認証情報の流出防止** | `T_認証アカウント` と **`T_認証アカウント_archive`** は一覧に出さず、MASTER でも出力を拒否 |
| MASTER 限定 | 監査ログ／ログイン履歴／メール送信ログ・明細／削除ログ／人物統合ログ／システム設定（**各アーカイブも同様**） |
| deny-by-default | テーブル定義・マスタ定義に無い名前は拒否。既定権限は MASTER のみ |
| **持ち出し記録** | 誰が・どのテーブルを・何行 出力したかを `T_監査ログ` に記録（**中身は記録しない**） |
| **CSV インジェクション対策** | `=` `+` `-` `@` で始まる値に `'` を前置し、Excel で数式として実行されないようにする |
| 画面の注意喚起 | 「個人情報が含まれる」「監査ログに記録される」「認証テーブルは出力できない」を常時表示 |

## 3. 途中で検出・修正した不具合（2 件）

### 3-1. 🔴 認証テーブルのアーカイブが出力対象に混入していた（v376.68.1 で是正）

- **検出**: 実装直後の live 画面確認で、一覧に `T_認証アカウント_archive` が現れた
- **原因**: 禁止判定を**完全一致**で行っていた。削除アーカイブ（`<テーブル名>_archive`）は
  元テーブルと同じ列を持つため、**パスワードハッシュとソルトを保持したまま出力できる状態**だった
- **是正**: `exportBaseTableName_()` で `_archive` を外してから判定する共通関数
  （`isExportForbiddenTable_` / `isExportMasterOnlyTable_`）を導入し、一覧・出力の**両方**が同じ判定を通るようにした
- **回帰固定**: unit test 3 件を追加（アーカイブ名の解決／禁止・MASTER 限定がアーカイブに及ぶこと／
  一覧と出力の両方が共通判定を通ること）。dryRun にも 2 チェックを追加

> **この不具合は dryRun では検出できなかった**（完全一致名しか試していなかったため）。
> 実画面の確認が効いた例として記録する。

### 3-2. 🟡 一覧の表示に 20 秒かかっていた（v376.68.2 で是正）

- **原因**: 56 シート分の `getSheetByName` + `getLastRow` を個別に呼んでいた
- **是正**: シート一覧を 1 回で取得し、**一覧では行数を返さない**（件数は出力後の結果で示す）
- **実測**: **20.0 秒 → 5.5 秒**

## 4. ビルドツールの罠（記録・再発防止）

`csvEscapeCell_` に **二重引用符を含む正規表現**（`/"/g` や `/[",\r\n]/`）を書いたところ、
build の関数抽出パーサが壊れ、**それ以降のすべての関数が検出されなくなった**（operator ツール 4 件が生成物から消失）。
ビルドが `operator tool functions missing` で落ちて発覚。

- **回避**: 正規表現を使わず `indexOf` / `split().join()` で実装。ソースにコメントで警告を残した
- **恒久対策**: パーサ自体の修正は 3 ファイルに複製されているため未実施。`docs/260` §4 の残課題に追加
