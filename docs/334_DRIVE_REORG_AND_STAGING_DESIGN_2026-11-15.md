**危険**
1. **公開リンク**: 共有ドライブに「組織外と共有しない」「メンバー以外と共有しない」の制限があると、移した時点で公開ポータルの PDF・サムネイルが見えなくなる。→ 棚卸しで共有ドライブの制限（`restrictions.domainUsersOnly`・`driveMembersOnly`）を読み、公開リンクが使えないなら公開しているフォルダは移さない。
2. **新しいファイルの作り先**: フォルダ・バックアップ・宛名リストなどは、コードがマイドライブ直下に作る。移しても新しいものは元の場所に作られ続ける → 第 2 段で「作り先を設定のフォルダにする」改修（ステージングと本番の分離の土台）。
3. 3 つの web アプリは `k.noguchi@hcm-n.org` の権限で動く（R1 で管理者と確認済み）。
4. よい点: Drive の REST 呼び出しはすべて `supportsAllDrives=true`。ファイルの ID は移動で変わらないので、保存した ID はそのまま使える。

## 4. 元に戻す方法（R5・D3 の詳細は D2 で確定）

- **記録**: 移す前に、資産ごとに「ID・名前・元の親フォルダの ID（すべて）・共有設定（アクセスと権限）・移動先」をログ用スプレッドシートの専用シートと、スクリプトプロパティ（最後の 1 回分）に書く。書けなければ移さない。
- **戻し**: `restoreDriveReorg_APPLY` が記録を読み、元の親フォルダへ戻し、共有設定を記録どおりに戻す。資産ごとに結果を出し、失敗したものは手で戻せるよう ID と元の場所をログに出す。
- **戻せることの確認**: 本番の前に、試し用のファイル・フォルダ（公開リンクつき）で「移す → 戻す」を通し、場所と共有設定が元どおりになることを確かめる。
- **移した後の確認**（1 つ移すごと）: `release:verify`（読み取り）、公開ポータルの研修一覧で PDF・サムネイルが表示されること、管理画面のダッシュボード。だめならその資産だけ戻す。
- Drive の画面からも手で戻せる（ID は変わらないので、元の親フォルダへドラッグ）。記録には元の場所の名前も残す。

## 7. D5 ステージングの設計（2026-11-15・下書き・operator 判断の後に確定）

**目的**: 本番と同じコードを、本番と切り離した環境で先に動かして確かめる（業界の定石の「ステージング」）。今は本番の DB に直接触れて確かめており、書き込みの確認は承認と後片付け（★テストデータの物理削除）が毎回要る。

| `rehearseDriveReorgRoundTrip_APPLY` | 試し用のファイル 2 つ（非公開・公開リンク）をマイドライブに作り、機密と公開の `ステージング/` へ**本番と同じ関数で**移し、場所と共有設定を確かめ、**同じ戻しの関数で**戻し、元どおりかを確かめ、最後にゴミ箱へ移す。全段の合否を出す |

- Drive の作成・移動は REST（`supportsAllDrives=true`・`addParents`/`removeParents`）。共有設定の読み書きは `DriveApp`。
- 移動の順番: 試し → 宛名リスト → ログ → LINE 投稿資材。1 回の実行で全部を移すが、1 件でも失敗したらそこで止め、それまでの記録で戻せる。
- 移した後の確認: `inventoryDriveAssets_LOG`（場所・公開リンクの件数が前と同じ）、管理画面（ログ用スプレッドシートに書く操作）、公開ポータルの LINE 投稿の画像。
