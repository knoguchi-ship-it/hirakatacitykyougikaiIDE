## 2. キーの規約

### 2.1 主キー

業務テーブルは原則として**先頭列に `◯◯ID` を持ち、それが主キー**である。
例外は `T_システム設定`（`設定キー`）と `T_共有メモ`（`キー`）で、キー文字列そのものが主キーになる。

**行番号を業務上のキーにしてはならない**（並べ替え・削除で変わるため。`AGENTS.md` §4.8 の NG パターン）。

### 2.2 採番方式（現状の実測）

| 対象 | 方式 | 例 |
|---|---|---|
| 会員ID | UUID をハッシュした **8 桁の数字** | `04831572` |
| 研修ID | `T` ＋ UUID 先頭 8 桁（大文字） | `T3F9A2C10` |
| 申込ID | `AP-` ＋ UUID 先頭 10 桁（大文字）。**採番は `generateTrainingApplyId_` の 1 関数に集約**（v376.72） | `AP-3F9A2C10BD` |
| 規程ID | `REG-` ＋ 連番 3 桁 | `REG-001` |
| 職員ID | `S` ＋ ミリ秒タイムスタンプ | `S1756900000000` |
| その他の多く | UUID そのまま | |

**会員ID だけは衝突しうる**（8 桁に縮めているため）。実装は生成後に既存を確認し、衝突したら 1 回だけ引き直す。

> **v376.72 で採番を統一した**（U-24 は解決済み）。それ以前は同じ `T_研修申込.申込ID` に **3 通りの形式**が
> 入っていた（会員セルフ = `AP-` ＋ 10 桁 ／ 外部申込 = 素の UUID ／ 管理の名簿手動追加 = `AP-` ＋ 8 桁）。
> **既存データは振り直していない**ため、古い 2 形式の ID も引き続き有効である
> （取消・照合はいずれも完全一致で引くため影響しない）。回帰は `npm run test:training-apply-id` が固定する。

### 2.3 外部キー（主要な関連）

| 子 | 親 | 列 |
|---|---|---|
| `T_事業所職員` | `T_会員` | 会員ID |
| `T_認証アカウント` | `T_会員` / `T_事業所職員` | 会員ID・職員ID（どちらか一方が入る） |
| `T_研修申込` | `T_研修` / `T_会員` / `T_事業所職員` / `T_外部申込者` | 研修ID ＋ 申込者区分コードで参照先が決まる |
| `T_年会費納入履歴` | `T_会員` | 会員ID |
| `T_支払い明細` | `T_支払い` / `T_請求` | 支払いID・請求ID |
| `T_役員` / `T_振込口座` / `T_請求` / `T_変更申請` | `T_会員` | 会員ID |

**参照整合性はデータベースが保証しない**（スプレッドシートのため）。アプリ側で担保する。
関連の全体像は ER 図（自動生成）を見ること。

## 3. 値の規約

| 項目 | 規約 |
|---|---|
| 日時 | **ISO 8601 の文字列**（`new Date().toISOString()`）。タイムゾーンは UTC 表記 |
| 日付 | `YYYY-MM-DD` の文字列 |
| 真偽値 | `true` / `false`（`削除フラグ` `有効フラグ` など） |
| コード値 | **英大文字のスネークケース**（`INDIVIDUAL` `BUSINESS_ADMIN` `WITHDRAWN` など）。表示名は `M_◯◯` 側に持つ |
| 金額 | 数値（円） |
| 空値 | **空文字**。`null` を書き込まない |
| 郵便番号・電話 | 検証パターンは `src/shared/validators.ts` が正本 |

**コード値と表示名を 2 か所に書かない**。判定はコード、表示はマスタから引く。

## 4. 削除の扱い

3 段階ある。**どれに当たるかをテーブルごとに決めており、混ぜない**。

| 方式 | 対象 | 挙動 |
|---|---|---|
| 論理削除 | ほとんどの業務テーブル | `削除フラグ = true`。行は残る |
| **アーカイブ移動** | 13 テーブル（`ARCHIVE_SOURCE_TABLES`） | `<名前>_archive` へ移し、元から消す。移送先には **アーカイブID / 削除バッチID / アーカイブ日時**の 3 列が加わる |
| 物理削除 | `T_ログイン履歴` | 復元しない。個人の接続元 IP を残さないため |

アーカイブは**会員削除に連動して 13 テーブルを一括で移す**（cascade）。同じ削除操作は同じ削除バッチIDでまとまる。

## 5. 内部インターフェース（画面 ⇄ サーバー）

### 5.1 単一エンドポイント

呼び出しは **`processApiRequest(action, payload)` の 1 本だけ**である。画面は `ApiClient`
（`src/services/api.ts`。メソッド数の正本はコード）越しにしか呼ばず、**`google.script.run` を直接触らない**
（GCP へ移すときに差し替えるため。`AGENTS.md` §4.8）。

### 5.2 応答の形

**必ず JSON 文字列**で返す。形は 2 つだけ。

```
成功: {"success": true,  "data": <任意>}
失敗: {"success": false, "error": "<理由>"}
```

`ApiClient` 側で `success` を見て、false なら例外に変換する。**画面は生の応答を解釈しない**。

### 5.3 認可（境界ごとに受け付ける action が違う）

配信している 3 つのアプリは、**そもそも受け付ける action の一覧が別**である。

| 境界 | 受け付ける action | 認証 |
|---|---|---|
| public | **18**（`PUBLIC_ALLOWED_ACTIONS`） | なし |
| member | **19**（`MEMBER_ALLOWED_ACTIONS`） | セッショントークン |
| admin | **118**（`ADMIN_ACTION_PERMISSIONS`・2026-09-04 実測）＋ ログイン用 1 | Google アカウント ＋ メニュー権限 |

一覧に無い action は `unsupported_action` で落ちる（**許可リスト方式・拒否が既定**）。
**件数は機能追加のたびに増える。正本は上記の定数**であり、`npm run security:split-boundary` と
`npm run test:menu-registry` が逸脱を検出する。

### 5.4 定型のエラー

| `error` | 意味 |
|---|---|
| `unsupported_action` | その境界では受け付けていない |
| `unauthorized` | 管理セッションが無い |
| `insufficient_permission` | メニュー権限が足りない |
| `member_unauthorized` | 会員のセッショントークンが無い |
| `member_session_expired` | セッションが切れた |

上記以外は例外のメッセージがそのまま入る。

### 5.5 なりすまし対策（重要な契約）

会員用の action では、**クライアントが申告した会員ID・職員ID・ログインIDを信用しない**。
サーバーがセッショントークンから解決した値で**上書きしてから**処理に渡す。
他人の ID を送っても他人のデータには届かない。

## 6. 外部インターフェース

| 相手 | 用途 | 契約 |
|---|---|---|
| **Gmail** | メール送信 | 出口は `deliverMail_` の 1 本だけ。4 段のガードと未解決マージタグの除去を必ず通す。送信元は登録済みエイリアスのみ |
| **Google Drive** | 研修案内 PDF・請求添付・一括メールの添付 | ファイルは URL で参照する。Drive の共有設定に権限制御を依存させない |
| **Cloud Run** | パスワードハッシュ（現在無効） | ID トークンで認証。詳細は TRD 第1部 §5 |

### 6.1 メールのマージタグ

差し込み文字列の**カタログは `src/shared/mailTemplates.ts` が正本**（14 カテゴリ）。
置換は `renderMergeTags_` の 1 本で行い、**解決できなかったタグは送信前に除去する**
（利用者に `{{会員種別}}` のまま届かないようにするため。v376.66/.67 の障害対応）。

### 6.2 CSV 出力（データ出力）

| 項目 | 仕様 |
|---|---|
| 文字コード | **UTF-8（BOM 付き）**。Excel でそのまま開けること |
| 区切り | カンマ。値に `"` 改行 カンマ を含む場合は `"` で囲み `"` を 2 つに重ねる |
| 1 回の上限 | **20,000 行**。超えたら打ち切り、打ち切ったことを画面に出す |
| 出せないもの | `T_認証アカウント` と **そのアーカイブ**（パスワードハッシュを含むため）。ログ・監査系は **MASTER のみ** |
| 記録 | 出力するたびに監査ログへ「誰が・どのテーブルを・何件」を残す |

**CSV の取り込み（インポート）は現在提供しない**（operator 判断・2026-09-03。再開時の対象範囲は台帳 `docs/261` T-07）。

## 7. スキーマを変えるときの手順

**同じターンで**次をすべて行う（`AGENTS.md` §3・§4.6）。

1. `gas-src/Code.full.gs` の `テーブル定義` / `マスタ定義` を更新する（**列の正本**）
2. **`DB_SCHEMA_VERSION` を上げる**。これを忘れると**新しいシートが作られず、画面が黙って空になる**（v376.65 で実際に起きた）
3. 必要なら `docs/er-metadata.json` に型・キー・関連を足す
4. `npm run build:docs-portal` で ER 図とテーブル設計書を再生成する
5. `npm run test:er-sync` を通す

## 8. GCP 移行後のデータ表現

Firestore へのマッピング原則（1 シート＝1 コレクション、`◯◯ID` をドキュメント ID、行番号を使わない、
数式を持たない）は **TRD 第2部 §11 が正本**。本書には再掲しない。

本書の規約のうち、**移行後も変えないもの**は次のとおり。

- 主キーの値そのもの（移行で振り直さない）
- コード値（`INDIVIDUAL` などの文字列）
- 日時の ISO 8601 表記
- 削除の 3 方式と、アーカイブの 3 列
- API の応答の形（`success` / `data` / `error`）と、なりすまし対策の契約

## 9. 本書に置かない節と、その正本

テンプレート（`docs/267`）の一部の節は**意図的に置いていない**。正本が別にあり、
書き写すと必ず古くなるため。省略した節と、代わりに見るべき場所は次のとおり。

| 置かない節 | 正本 | 変更したときの手順 |
|---|---|---|
| テーブルごとの列定義（型・NULL・制約） | `gas-src/Code.full.gs` の `テーブル定義` / `マスタ定義` | §7 の 5 手順。`docs/portal/tables.html` と ER 図が自動再生成される |
| 個別 API の Request / Response JSON（メソッド数の正本はコード） | `src/services/api.ts` の `ApiClient` 型定義（コンパイラが検査） | 型を直す。応答の形（§5.2）とエラーコード（§5.4）は本書が正本 |
| 入力バリデーションの値（桁数・パターン） | `src/shared/validators.ts` | 値を直す。`npm run test:single-source` が二重定義を検出する |
| 画面ごとの入力フォーム定義 | UI/UX 定義書（画面の構成）＋ 上記 `validators.ts`（規則） | — |

**この一覧に無い節を黙って省略しない。** 省くときは、ここに理由と正本を追記する。
