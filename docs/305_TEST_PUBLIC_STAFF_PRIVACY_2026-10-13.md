# 305 公開ポータル 職員の照合方式 — テスト観点表と結果（2026-10-13）

対象の変更: 公開ポータルで登録済みの個人情報を見せない（`docs/304` H1 の operator 判断）。
- 職員一覧・在籍人数を返す公開 action を廃止
- 職員の情報変更・除籍は登録されている「氏名＋介護支援専門員番号」で照合する
- 職員数の上限は承認時に申請全体で確かめる
- 承認画面に職員情報の変更内容を表示する

状態: **未リリース**（本番は修正前のコード）。

### 3.1 実施の条件

- 公開ポータルは `npm run dev` の `index_public.html`。`google.script.run` を模擬し、§1 のテストデータで応答させた。
- 承認画面は `.tmp/harness/cr.html`（git 対象外）で `ChangeRequestConsole` だけを描画した。確認ダイアログは自動で「OK」にした。
- 画面は実際の GAS を通していない。サーバの処理は S-01〜S-06（生成物の関数を実行）で確かめた。

### 3.2 テスト中に見つけて直したもの

1. **項目名のラベルが入力欄に結び付いていなかった。** スクリーンリーダーで項目名が読まれない。
   最初は照合欄・変更欄だけ直したが、画面で数え直すと**この画面の大半**（事業所 22 中 16・個人 23 中 22）が同じだった。
   28 か所すべてを `htmlFor` と `id` で結び付けた（P-19）。
   - 教訓: 最初の計測は「0 件」と出たが、項目の選択が効かず入力画面に進んでいなかった。**0 件を合格と読まず、母数を確かめる。**
2. **照合していないカードがあると送信ボタンは押せないが、理由が画面に出なかった。**
   理由はマウスを重ねたときの説明（title）にしか無かった。ボタンの下に、照合が済んでいないカードを名指しする案内を出すようにした。
3. **項目名の「今の」を外した**（operator 指摘）。「今の氏（姓）」→「氏（姓）」など、画面の文言 7 か所。
4. **途中まで入力した職員追加カードが、申請から黙って外れていた。** 送信時の絞り込みで落ち、申請は成功する。
   申請者は追加を申請したつもりになる。送信前に止め、カードを名指しする（P-17）。
5. **送信エラーが、スマホ幅では見えない位置に出ていた。** エラーは画面上端、送信ボタンは下端にある。
   エラーが出たら画面内へ移してフォーカスを当てる（P-18）。
6. **個人・賛助会員の申請でも、サーバが職員追加を受け付けていた。** 画面は事業所会員にしか欄を出さないが、
   API を直接呼べば通り、承認すると会員IDの下に職員行が作られる。事業所会員以外は拒否する（S-07）。
7. **承認時に職員の追加・除籍ができなくても、申請は承認済になり誰にも知らされなかった。**
   重複などで追加に失敗した場合と、承認までに職員が改姓・除籍されて照合できない場合。Chat の異常通知へ出す（S-08）。
8. **職員追加（STAFF_ADD）の承認で、追加に失敗した職員にも「追加しました」のメールを送っていた。**
   代表者への通知にも失敗した職員の名前が入っていた。追加できた職員だけを対象にする（S-09）。
