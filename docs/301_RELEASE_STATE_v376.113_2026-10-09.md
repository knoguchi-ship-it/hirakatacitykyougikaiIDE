## 1. 何が起きていたか

「読み込みにかなりの時間がかかる」という指摘を受け、本番を計測して原因を切り分けた。

| 区分 | 内容 | 扱い |
|---|---|---|
| **Apps Script の限界** | 呼び出し 1 回あたり約 2 秒の固定費（応答 80 バイトでも 1.9〜2.5 秒）／HTML 配信約 1.5 秒＋コールドスタート／配信 HTML が CDN キャッシュされない／PBKDF2 1 万回で 2〜4 秒／CacheService がプロジェクト単位 | **触らない。** 固定費の解消は GCP 移行（`docs/250`）の領域。PBKDF2 を下げる・3 境界でキャッシュを共有する案は、セキュリティ境界に逆行するので採らない |
| **実装起因** | 下表の 5 件 | **今回すべて是正** |

### 実装起因の 5 件

| # | 何が起きていたか | なぜ起きていたか |
|---|---|---|
| B1 | 会員・管理画面を開くたびに、HEIC 変換用の 1.3MB の Worker が **2 つ**起動していた | `heic2any` を静的 import していた。このライブラリは読み込んだ時点で Worker を起動する。CommonJS 経由だと本体を 2 回生成する（`module.exports = a(); module.exports.default = a();`）。使うのは役員の請求添付だけ |
| B2 | 会員マイページに管理画面一式、管理画面に会員マイページ一式が入っていた（どちらも 2.4MB） | 会員・管理とも同じ `src/index.tsx` から作られ、画面の分岐が実行時の状態だけで決まっていたため、ビルドで落とせなかった |
| B3 | 管理 API を 1 回呼ぶたびに `T_ログイン履歴` へ 1 行書き、表示名のためだけに `T_会員` を全件読んでいた | 認可のために全 API が通る `checkAdminBySession_` が、成功を毎回記録していた。表示名はキャッシュが管理 split ではほぼ作られず、毎回シートから引いていた |
| B4 | ダッシュボードと会員マイページの取得で、`T_会員`・`T_研修`・`T_事業所職員`（マイページは `T_認証アカウント` も）を 2 回ずつ読んでいた | `getTrainingApplicationRows_` に読み込み済みの行を渡しておらず、妥当性検査用に読み直していた |
| B5 | 管理画面の起動が「認証 → 初期データ → メールテンプレート」の 3 段直列だった | テンプレート一覧を設定の読込直後に取っていた（使うのは設定画面だけ）。初期データは認証の応答を待ってから投げていた |

## 2. どう直したか

| # | 修正 |
|---|---|
| B1 | `src/lib/heic2anyLoader.ts` を新設。ライブラリを `?raw` で**文字列として同梱**し、HEIC を選んだときに初めて評価する。UMD の **AMD 分岐**へ流して本体を 1 回だけ生成し、`window` も汚さない |
| B2 | `renderContent` と `renderMemberView` を `import.meta.env.VITE_APP`（ビルド時に定数へ置換される）で閉じた。会員ビルドは管理画面を、管理ビルドは会員マイページを tree-shake で落とす。管理 split で会員マイページへ落ちる経路は、もともとデータ取得 API が無く表示できなかったので、v250 確定の方針どおり案内文を出す |
| B3 | `checkAdminBySession_(options)` を新設。成功の記録は `recordLogin: true` を渡すログイン操作（action `checkAdminBySession`）だけ。**失敗はどの経路でも従来どおり必ず記録する。** 表示名は `admin_name_v1:<会員ID>` に 5 分キャッシュ |
| B4 | 両関数とも `getRowsAsObjectsBatch_` で必要なシートを 1 回ずつ読み、行と relation context を `getTrainingApplicationRows_` へ渡す |
| B5 | 管理 shell の起動で、認証確認と同時に `getAdminInitData` を先行取得する（サーバ側で毎回認証・認可を通すので、権限の無い人には何も返らない）。初期画面がダッシュボード以外なら結果は捨てる。テンプレート一覧は設定画面を開いたときに取得 |

### 採らなかった方法と理由

- **動的 `import('heic2any')`**: vite-plugin-singlefile が 1 ファイルへインライン化し、**起動時に評価されたまま**だった。
  さらに Vite の preload ヘルパが `import.meta` を持ち込み、起動ローダーの `new Function()` と非互換になる
  （v351 の pdfjs、v360 の SheetJS と同じ罠）。`compress-html.mjs` が `import.meta` を検出して止める。
- **HEIC 対応の廃止**: 会員の配信 HTML（723KB）の大半は HEIC 変換ライブラリ本体だが、機能の削除にあたるので今回は見送った。
