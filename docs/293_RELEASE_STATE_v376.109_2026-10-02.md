# v376.109 — プライバシーポリシーをリンクにし、URL をコードから追い出す（2026-10-02）

## 1. 何が問題だったか

operator 指摘:

> プライバシーポリシーは本サイトに掲載しています。を プライバシーポリシーについて とし
> この文字をハイパーリンク化 リンク先を https://sites.google.com/view/starhirakata/privacy-policy にしてほしい。

公開ポータルのフッターと研修の外部申込フォームは、どちらも
**「プライバシーポリシーは本サイトに掲載しています。」とだけ書いて、どこへも繋いでいなかった。**
読み手は掲載場所を自力で探すしかない。

同じ形の問題がもう 1 件あった。入会申込の「定款を確認する」が **古い掲載先を指したまま**だった
（`T_規程` の REG-005）。協議会が定款の置き場所を移したが、システム側は追随していない。

二つに共通するのは、**行き先がこのシステムの外にあり、しかもリリースしないと変えられない場所に
書かれていた**こと。URL は協議会の都合で動くのに、変えるのが開発作業になっていた。

## 2. どこに持たせるか（operator との合意）

operator 提案:

> スクリプトプロパティに設定しましょう。Dry原則です。どうでしょうか？

**採らなかった。理由は ScriptProperties が GAS プロジェクト単位だから。**
本システムは統合・公開 / 会員 / 管理者の 3 プロジェクトに分かれており、ScriptProperties に置くと
**同じ URL を 3 か所に別々に登録する**ことになる。DRY にするつもりが逆に 3 重管理になる。

採ったのは `T_システム設定`（共有 DB スプレッドシート `DB_SPREADSHEET_ID_FIXED` 上）。
3 split のどこからでも読め、管理画面から編集でき、既存のメール設定などと同じ仕組みに乗る。

さらに operator 指摘:

> この設定については、これまで編集してきたシステム管理（メールなど）とは一線を画すと考えます。
> もっとシステム関連の設定として別枠としたいと考えますがどう考えますか？

合意のうえ、公開ポータルタブの先頭に **「サイト情報」** という見出しを新設した。
文面・本文の編集とは別枠にし、「このシステムの外にある掲載先を指す設定」をここに集める。
定款 URL も将来ここへ寄せられる（今回は `T_規程` のデータ修正で足りたため移していない）。

## 3. 変更内容

### 設定キー

`PUBLIC_PORTAL_PRIVACY_POLICY_URL` を `T_システム設定` に追加。`gas-src/Code.full.gs` の 7 か所
（`PUBLIC_PORTAL_DEFAULTS` / `getSystemSettings` の読み出しと返却 / `updateSystemSettings` の書き込み /
シード行 / `getPublicPortalSettings` の読み出しと返却）を通す。

**既定値は空文字。「既定として使われる URL」はソースのどこにも無い。**
ハードコードされた既定値こそが定款リンクを腐らせた原因なので、同じ轍を踏まない。
`test:privacy-policy-link` が、3 面すべてで既定値が空であること、および公開ポータル本体と
研修申込画面に `privacy-policy` の文字列が現れないことを検査する
（管理画面は入力欄のプレースホルダで例示するため対象外）。

**空を保存したら空が保存される。** 他の設定は `値 || 既定値` で書くが、このキーだけは
`|| 既定値` を付けていない。付けると「リンクを消す」操作ができなくなる。

### 表示

- フッター（`src/public-portal/App.tsx`）: 設定が空なら**要素ごと出さない**。
  行き先の無いリンクを出すより、何も出さないほうが正しい。
  値があれば `プライバシーポリシーについて` を `target="_blank" rel="noopener noreferrer"` のリンクで出す。
- 外部申込フォーム（`ExternalApplyForm.tsx`）: 同意文を
  「…第三者への提供は行いません。」で止め、設定があるときだけ
  「詳しくは<u>プライバシーポリシー</u>をご確認ください。」を続ける。

operator 指示:

> 本サイトに掲載していますは不要です。リンクであるため、リンクであることを前提に元文章の訂正もお願いします。

リンクになった以上、掲載場所を説明する一文は雑音なので両方から落とした。

### 管理画面

`src/App.tsx` の公開ポータルタブ先頭に「サイト情報」見出しと `type="url"` の入力欄。
プレースホルダは例示のみ（`例: https://sites.google.com/view/starhirakata/privacy-policy`）で、
未入力時に既定値として使われることはない。

## 4. 定款 URL は「データ」として直した

`T_規程` の REG-005 を新しい掲載先（`https://sites.google.com/view/starhirakata/incorporation`）へ更新。
**リリースは不要だった** — これがまさに、今回プライバシーポリシーにも持たせたかった性質である。

## 6. 実装中に見つけたこと

### `updateSystemSettings` は部分更新できない

1 キーだけ送ったら **「年会費の振込先が未設定です。」で拒否**された。
`validateAnnualFeeTransferAccount_(request.annualFeeTransferAccount)` が無条件で走るため、
**この API は常に全設定を含むペイロードを要求する**。
対処は read-modify-write（`getSystemSettings` → 1 キーだけ差し替え → `updateSystemSettings`）。
今回は保存前後で全キーを突き合わせ、巻き添え変更が 0 件であることを確認している。
**今後この API を叩くツールやスクリプトを書くときは、必ず read-modify-write にすること。**

### 自分の手順の誤り 2 件（記録として残す）

- 管理画面のサイドバーで「システム」グループが**畳まれていた**ため、UI 操作が空振りした。
  画面が出ないことを実装の問題と早合点しかけた。
- `getPublicPortalSettings` を**管理画面のフレームから呼んだ**。これは公開 split 専用の action なので
  何も返らない。公開ポータルの実画面で確認し直した。
