# 公開ポータルの文言: 案内文は定型文から選ぶ・見出しは空欄にできない（2026-10-25）

`docs/307` F26 の本対応。operator 決定（2026-10-25）:
「空白を許可しない形にしましょう。デフォルト文の template を定型文に入れておき、template をゼロにはできない設定にして、
どの template のメッセージかを設定で必ず選ばせる」。

## 1. 何が問題だったか

公開ポータルの文言（入会完了画面の案内文・トップや各カードの見出し・説明・ボタン名）は、設定が空だと
**読むときにプログラムの中の既定の文面で補っていた**。既定の文面は 4 か所（GAS `PUBLIC_PORTAL_DEFAULTS`・
管理画面 `src/App.tsx`・公開ポータル `src/public-portal/App.tsx`・入会フォーム `MemberApplicationForm.tsx`）に同じものを持ち、

- 設定画面で空にして保存しても、画面には別の文面（コードの既定）が出る。事務局は何が出るかを設定から知れない
- 4 か所のどれかだけ直すと、画面ごとに違う文面になる（v376.131 で 4 か所をそろえ直した）
- 設定の取得に失敗したときも既定の文面で表示を続けていた（fail-open）

## 2. 決めたこと

| 種類 | 対象 | 扱い |
|---|---|---|
| 案内文（長い文章） | 入会完了画面の「今後のご案内」（送信 ON / OFF）・ログイン情報の補足（送信 ON / OFF）の **4 用途** | **定型文の表から選ぶ**。設定には選んだ定型文の ID だけを持つ |
| 見出し・説明・ボタン名（短い言葉） | トップ・入会・研修・登録情報変更・退会の **19 項目** | **空欄では保存できない**。読むときの補完をやめる |
| 旧い案内文 2 項目 | `PUBLIC_PORTAL_COMPLETION_CREDENTIAL_NOTICE` / `_NO_CREDENTIAL_NOTICE` | 案内文が空のときの補完にしか使っていなかった（設定画面にも出ていない）。**読むのをやめる** |

当初は案内文を 6 項目と数えたが、うち 2 項目は上の旧い補完用で、画面で編集できるのは 4 用途だけだった。

## 3. 表 `T_画面文テンプレート`

| 列 | 内容 |
|---|---|
| テンプレートID | 主キー（`STT-` ＋ UUID 先頭 8 桁） |
| 用途コード | `COMPLETION_GUIDANCE_SENT` / `COMPLETION_GUIDANCE_NOT_SENT` / `COMPLETION_LOGIN_INFO_SENT` / `COMPLETION_LOGIN_INFO_NOT_SENT` |
| 名前 | 一覧で見分けるための名前（必須） |
| 本文 | 表示する文章（必須・空白だけは不可） |
| 表示順 | 一覧の並び |
| 作成日時・更新日時・削除フラグ | 共通 |

- 既存の `T_メールテンプレート` とは混ぜない。あちらは「名前を付けて保存・読み込み」する写しで、送る本文は設定側に別に持つ（今回なくしたい二重持ちそのもの）。
- 用途コードは設定キーと 1 対 1 で、プログラムの動き（どの画面のどの枠か）を決める値なので、M_ マスタにはしない（`SCREEN_TEXT_TEMPLATE_PURPOSES_`）。
- 会員・職員と結び付かない。`TEST_DATA_PURGE_TABLE_POLICY` は `NONE`、アーカイブ・削除の連動の対象外。

設定キー（新設・4 つ）: `PUBLIC_PORTAL_COMPLETION_GUIDANCE_TEMPLATE_ID_WHEN_CREDENTIAL_SENT` ほか。
**旧い本文のキーは書き換えない**（前の版へ戻したとき、旧いコードがそのまま本文として読めるように残す）。

## 4. サーバーが必ず止めること（画面の操作だけに頼らない）

1. 設定で選ばれている定型文は削除できない
2. その用途の最後の 1 件は削除できない（0 件にできない）
3. 名前・本文が空（空白だけ）の定型文は保存できない
4. 存在しない ID・削除済みの ID・別の用途の ID は設定で選べない
5. 見出し・説明・ボタン名 19 項目は空欄で保存できない

## 5. 移し替え（スキーマ整備・今の表示を変えない）

- 定型文が 1 件も無い用途に、**今の画面に出ている文面**（設定の値、空なら旧い補完と同じ組み立て）を「移行時の文面」として 1 件作り、それを選んだ状態にする。
- 見出し・説明・ボタン名が空の項目は、今の画面に出ている文面（コードの既定）で埋める。
- 2 回流しても増えない（定型文がある用途・空でない項目には触れない）。

初期データ（新しく DB を作るとき・移し替え）にだけ `PUBLIC_PORTAL_DEFAULTS` の文面を使う。M_ マスタの初期データと同じ扱い。

## 6. 読むとき

- 案内文: 選ばれた ID の定型文の本文。**見つからなければ空**にし、公開ポータルはその枠を出さない。管理画面の設定に警告を出す。
- 見出しなど: 設定の値そのまま（補わない）。
- 公開ポータルの設定の取得に失敗したとき: 既定の文面で表示を続けるのをやめ、「画面の設定を読み込めませんでした」と再読み込みの案内を出す（接続の再試行は今までどおり 5 回）。

## 7. 画面（管理 → システム設定 → 公開ポータル → 入会完了画面の文言設定）

各用途の枠に「使う定型文」の選択と、その用途の定型文の一覧（追加・編集・削除）を出す。「デフォルトに戻す」ボタンは無くす（既定の文面は定型文として一覧にある）。

## 8. 検査

- `test:screen-text-templates`: 4 つの禁止（選択中・最後の 1 件・空・別用途）、移し替えが今の表示と同じで 2 回目に増えない、読むときに補わない、見出しの空欄を止める
- 既定の文面の直書きが `src/` に残っていないこと（`test:completion-defaults` を置き換え）
- `audit:db-model`（表・ER・削除の扱い）・本番 DB のコピーでのリハーサル
