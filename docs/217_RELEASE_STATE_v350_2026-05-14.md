# Release State v350

Date: 2026-05-14
Status: production deployed

## Scope

v349 deploy 後、本番で「アップロードしたばかりの研修にサムネイルが出ない」事象が
継続観測された（uploadTrainingFile_ が `thumbnailUrl='' `を返し、画面では PdfThumbnail
そのものが非表示、または SVG プレースホルダ表示）。Web 検索によるベストプラクティス
再評価の結果、v349 の retry が不足していた / 失敗時の救済 UI が無いことが判明し、
**polling 戦略の強化 + 後追い backfill trigger + 手動再生成 UI** の 3 点を入れた。

## Web 検索で確定したベストプラクティス

| 観察事実 | 出典 |
|---|---|
| 新規 PDF アップロード直後の `thumbnailLink` は **しばしば null**（Drive 側で thumbnail render が間に合わない） | [Latenode community](https://community.latenode.com/t/missing-thumbnail-url-when-uploading-pdf-files-to-google-drive-api/36251) |
| 公式推奨: **10〜15 秒初動待ち + その後 30 秒毎に 5 分まで polling** | 同上 |
| 大きな PDF は **20+ 分** かかる事例あり | 同上 |
| `thumbnailLink` 単体ではなく **`hasThumbnail` boolean field** を生成完了の真実情報とすべし | [Drive API v3 guide](https://developers.google.com/workspace/drive/api/guides/file-metadata) |
| `contentHints.thumbnail` は自動生成優先のため PDF には効かない | 同上 |
| `thumbnailVersion` field は cache invalidation 用で生成状況検知には使えない | [Drive API v2 reference](https://developers.google.com/drive/api/reference/rest/v2/files) |

## v350 変更内容

### `gas-src/Code.full.gs`

1. **`generateAndSaveThumbnailForPdf_` の polling 強化**:
   - retry 3 回 → **5 回**、sleep 3s/4s/4s → **5s × 5 = 最大 25 秒**
   - `files.get?fields=thumbnailLink,hasThumbnail,mimeType` で取得し、
     **`hasThumbnail===true` かつ `thumbnailLink` 存在** を成功条件とする
   - 25 秒で間に合わない場合は空文字を返し、後段 trigger に委譲

2. **`uploadTrainingFile_` の返却拡張**:
   - 既存: `{ url, driveFileId, thumbnailUrl }`
   - 追加: `thumbnailGenerationStatus: 'generated' | 'pending' | 'failed' | 'skipped'`
   - client が UX 切替に使う

3. **`processPendingThumbnails` (admin top-level, time-trigger 用)**:
   - 10 分毎に T_研修 を走査
   - `案内状サムネイルURL` 空 + `案内状URL` 有 の行を最大 5 件処理
   - 同じ pipeline で生成・更新
   - 20+ 分かかる大きな PDF も繰り返し trigger で最終的に救済

4. **`setupPendingThumbnailsTrigger` (admin top-level, 1 回登録用)**:
   - Apps Script editor から関数を選んで Run するだけで 10 分毎トリガー登録
   - 冪等（既存同名 trigger を削除して再登録）

5. **`regenerateThumbnailForTraining_` (admin action)**:
   - 単一研修だけ即時再生成
   - 編集モーダルの「サムネイル再生成」ボタンから呼ばれる
   - 返却: `{ trainingId, thumbnailUrl, thumbnailGenerationStatus, reason? }`
   - ACL: MASTER / ADMIN / TRAINING_MANAGER / TRAINING_REGISTRAR

### Client (React)

1. **`api.regenerateThumbnailForTraining(trainingId)`** を ApiClient に追加
2. **`uploadTrainingFile` 返り値の型に `thumbnailGenerationStatus` 追加**
3. **`TrainingManagement` フォーム**:
   - `thumbnailStatus` / `thumbnailStatusMsg` の状態管理追加
   - アップロード結果の status を反映
   - PDF preview 横に **「サムネイル再生成」ボタン**（既存研修のみ）
   - pending / failed 時に色分けメッセージ表示

### Boundary

- `audit-admin-boundary.mjs` / `build-admin-gas.mjs`:
  - admin allowed actions に `regenerateThumbnailForTraining` 追加
  - admin top-level functions に `processPendingThumbnails`, `setupPendingThumbnailsTrigger`
    追加（v349 の `regenerateAllThumbnails` と並ぶ）
- member / public artifact からは build 時 pruning で除去

## Operator one-time setup (重要)

1. https://script.google.com/u/0/home → admin split プロジェクト
   (`1tlBJ-OJjqNQQxzb5tY3iRUlS4DmQD9sYqw5j842tXD1SPVHutBUeKTRi`) を開く
2. 関数選択ドロップダウンで **`setupPendingThumbnailsTrigger`** を選んで Run
3. 実行ログに `setupPendingThumbnailsTrigger: trigger installed (every 10 min)` が
   出ることを確認
4. 以降、10 分毎に `processPendingThumbnails` が走り、サムネイル未生成の研修を
   自動 backfill する

## Operator residual checks

1. **新規アップロード**: 管理者ポータルで研修編集 → PDF アップロード → 約 20〜25 秒で
   サムネイル画像がフォームに出る。出ない場合は「サムネイル再生成」ボタンが
   フォームに表示される。
2. **既存「令和8年度…」など pending 状態の研修**: 編集モーダルを開き、
   「サムネイル再生成」ボタンをクリック。即時生成可能ならその場で反映、
   Drive 側がまだ完了していない場合は "1〜5 分待って再試行してください" メッセージ。
3. **完全 backfill**: `setupPendingThumbnailsTrigger` 実行後、最大 10 分後に
   自動 backfill が走り始める。または `regenerateAllThumbnails` (v349) を Run。
