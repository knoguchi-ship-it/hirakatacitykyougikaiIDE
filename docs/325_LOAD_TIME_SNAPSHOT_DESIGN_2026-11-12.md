## 3. 設計の方針（operator と合意した内容と、その理由）

### 3.1 読むときに組み立てない（完成品方式・CQRS の読み取りモデル）

- この協議会のデータは**読む回数が書く回数より桁違いに多い**（会員数百・書き込みは 1 日数回）。
  いまは画面を開くたびに 6 枚の表を読み、結び付け、集計している。
- 書いたときに**画面単位の完成品 JSON**を作っておく。対象は**今年度と前年度**に絞り、それより古いものは表示の後に裏で読む（operator 案）。
- **スプレッドシートを読み込みの経路から外す**（operator 案・実測でも DB を開く・表を読むが重い見込み）。

### 3.2 一番速い置き場は「HTML そのもの」

- 置き場をプロパティにするかキャッシュにするかの差は数十ミリ秒の見込み。**呼び出しを 1 回減らす（1.5 秒）方が 30 倍以上効く**。
- doGet の中で `getProperties()` を **1 回**呼べば分割した完成品が全部返る。それを HTML に埋め込めば、画面が出るまでの追加の呼び出しは 0 回。

### 3.3 スクリプトプロパティを置き場にする（operator の指摘で方針を改めた）

- 当初 AI は「プロパティはデータの置き場に向かない」と言ったが、**言い過ぎで撤回した**。
- 理由: 大きさは収まる（管理の初期データ 135 KB・公開用は数十 KB・上限は 1 値 9 KB／合計 500 KB）。
  キャッシュと違い**消えない**ので、20 秒かかった「冷えた状態」が無くなる。
- **個人情報を置くことも可**（operator の指摘で撤回）: プロパティを読めるのはスクリプトの編集者だけで、その人は元々 DB 全体を読める。
  見られる人の範囲は広がらない。**ただしブラウザの localStorage は別**（同じパソコンを使う未ログインの人に見える・共用 PC がある）→ 非推奨のまま。

### 3.4 実装で必ず守ること（つまずきどころ）

| # | つまずき | 対処 |
|---|---|---|
| 1 | 分割して書いている途中に読むと**新旧が混ざる**（いまの `getChunkedCache_` も混在は検知しない） | 新しい版を別名（`snap:v42:0…`）で書き終えてから「現在の版」を指す 1 件だけを替える（ポインタの切り替え） |

| 4 | 完成品は全項目の「親」 | **配信する前に権限ごとに絞る**（研修登録者などに会員一覧を渡さない）。いまの `getAdminInitData` が権限で絞っているかは**未確認** |
| 5 | 削除の義務が写しにも及ぶ | 退会者・テストデータの物理削除の後は完成品も作り直す。古い版の断片を残さない |

| 8 | 作り直しの速さ | 6 枚を Sheets REST `values:batchGet` の 1 回で読む（`docs` 既知の罠: API で書いた直後に SpreadsheetApp で読まない） |

### 6.3 ここから言えること（設計への反映）

1. **プロパティもキャッシュも 1 回 5〜50 ms**。45 KB を足しても `getProperties()` は 23 ms。**完成品の置き場としてプロパティは十分速い**（operator の見立てどおり）。

2. **重いのは表の読み込み**。SpreadsheetApp で 6 枚 3 秒 → **REST の batchGet で 0.6 秒**。完成品を作り直す処理（書いた後に走る）は batchGet で作る。
   段 1 でも、読み込みの多い処理（設定・公開設定・ダッシュボードの作り直し）を batchGet に替えるだけで秒単位で縮む見込み。
3. **H1（DB を開き直す）は外れ**。`getOrCreateDatabase_()` を覚えさせても効果はほぼ無い → 段 1 から外す。
   代わりに「最初に表へ触れたときの約 0.3〜0.5 秒」がある。1 回の要求で表に触れる回数を 0 にする（完成品方式）のが本筋。
4. **設定の読み込み（`getSystemSettings_` 1.1〜1.9 秒・`getPublicPortalSettings_` 1.0〜1.6 秒）が単独で最大**。管理の初期データにも公開ポータルにも毎回入る。
   完成品方式の最初の対象は「設定」でよい（公開・管理の両方に効く・個人情報なし・133 行で小さい）。
5. **説明できない差が残る**: web app 経由の `getAdminChangeRequests` は 4.7 秒。固定費 1.5 秒＋エディタで計った中身（認証 0.4・最初の表 0.4・本体 0.4）で約 2.7 秒。
