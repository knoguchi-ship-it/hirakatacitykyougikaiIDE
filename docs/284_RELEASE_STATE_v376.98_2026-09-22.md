# v376.98 リリース状態（2026-09-22）

## 1. 結論

メール通知の差し込み（マージタグ）を、一覧表示から**クリックで挿入するボタン**に変えた。あわせて、表示されるタグが実際に使えるタグと食い違っていた不具合を解消した。

変更前は `マージタグ: {{氏名}} (氏名) {{ログインID}} (ログインID) …` と並べるだけで、利用者は読んで手で打ち込む必要があった。説明の大半はタグ名の繰り返しで、読む価値もなかった。

バックエンドの変更はない。差し込みタグのカタログ（`src/shared/mailTemplates.ts`）も変えていない。

## 2. 変更内容

### 2-1 挿入 UI

- カード内に「差し込み」ボタンを置き、押すと**件名・本文のカーソル位置へ挿入**する。選択範囲があれば置換する。
- 挿入後はカーソルをタグの直後へ戻し、続けて入力・挿入できるようにした。
- 挿入先（件名／本文）は最後にフォーカスした欄。**押す前から、どちらに入るかを表示する。**
- ボタンは `mousedown` の既定動作を止めてフォーカスを奪わない。奪うと入力欄のカーソル位置が失われる。
- 押した直後は結果を文（「「氏名」を本文に入れました」）で返す。ボタン側の文言は変えない。変えると幅が動いて押しにくくなる。
- 説明はタグ名が意味を含まないときだけ添える。判定は「タグ名が説明を含むか」。
  - `{{氏名}}`／氏名 → 出さない
  - `{{会員マイページURL}}`／マイページURL → 出さない（言い換えでしかない）
  - `{{パスワード}}`／初期パスワード → 出す（「初期」が意味を足す）

### 2-2 表示タグと実際に使えるタグの不一致の解消

| 不具合 | 内容 |
|---|---|
| 表示漏れ | 事業所・メンバー向けのタグ（`BIZ_STAFF`）がどのカードにも表示されていなかった |
| 過剰表示 | 職員追加 2 枚と申請ワークフロー 3 枚が複数種別の和集合を表示していた。受付確認カードに、そのメールでは使えない `{{処理備考}}` などが並んでいた |

過剰表示は、挿入して保存しても送信時に `stripUnresolvedMergeTags_` が黙って落とすだけで、利用者には理由が分からない状態だった。

タグはカードのメール種別（`templateCategory`）から `MAIL_TEMPLATE_MERGE_TAGS` を引く形に変え、**種別とタグが必ず一致する**ようにした。ワークフロー見出しにあった差込変数の直書き列挙も削除した（同じ二重管理のため）。使われなくなった `MergeTags` と `mergeTagUnion` を削除した。

## 5. GCP 移植メモ

挿入 UI は表示層だけの関心事であり、Cloud Run 側の通知アダプタには影響しない。ただし「カードのメール種別からタグを引く」という結び付けは移植先でも維持すること。種別とタグを別々に持つと、今回直した不一致が再発する。

## 6. 追補: v376.98.1（同日）

差し込みボタンを押すと本文が一番下までスクロールし、編集していた場所を見失うとの指摘を受けて修正した。

**原因**: 本文を一度もクリックしていないときは末尾へ追記し、その後 `focus()` を呼んでいた。`focus()` は既定でカーソル位置までスクロールするため、末尾まで一気に飛んでいた。クリック済みの場合は `focus()` が無効果のため発生せず、v376.98 の検証でカーソル位置だけを見てスクロール量を測っていなかったので見逃した。

**修正**:

- 位置を決めてから focus する順序にし、`focus({ preventScroll: true })` でスクロールを抑止する。
- 押す前の `scrollTop` を挿入後に復元し、見えていた範囲をそのまま保つ。
- 直近のカーソル位置を欄ごとに覚え、フォーカスが外れていてもそこへ挿入する。末尾追記になる場面自体を減らす。

**検証**: 素の DOM で両経路を再現し、未フォーカス経路で `scrollTop` が 40 → 476（最下部）になること、修正後は 40 のまま留まることを確認した。

**デプロイ**: integrated/public @409 x2 / member @167 / admin @264。
