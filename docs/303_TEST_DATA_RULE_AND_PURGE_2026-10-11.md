# テストデータのルールと物理削除（2026-10-11）

**operator 決定（2026-10-11）**: 会員マイページは実データで確認する。必要に応じてテスト会員を作り、
終わったら**物理削除**する（論理削除ではない。テストデータで DB を圧迫しないため）。
テストデータは印で、実データと間違いなく見分けられるようにする。

## 1. ルール — テストデータの印

**印は 2 つ。両方そろったものだけがテストデータ。** 片方だけでは消さない。

| 種別 | 名前の先頭に★を付ける列 | メールアドレス |
|---|---|---|
| 個人会員・賛助会員 | `T_会員.姓` | `代表メールアドレス` を `@example.invalid` |
| 事業所会員 | `T_会員.勤務先名`（事業所名） | `代表メールアドレス` を `@example.invalid` |
| 事業所職員 | `T_事業所職員.姓`（空なら `氏名`） | `メールアドレス` を `@example.invalid` |
| 外部申込者 | `T_外部申込者.氏名` | `メールアドレス` を `@example.invalid` |
| 承認前の入会申込 | `T_変更申請.申請者表示名` | `連絡先メールアドレス` を `@example.invalid` |

- `@example.invalid` は RFC 6761 の予約ドメインで、どこにも届かない。
- ★は黒い★（U+2605）。白い☆は印ではない。先頭の空白は無視する。
- ステータス（在籍中など）の列には付けない。業務の判定に使っているため。
- 判定の正本は gas-src の `isTestMemberRow_` / `isTestStaffRow_` / `isTestExternalApplicantRow_` /
  `isTestChangeRequestRow_`（`TEST_DATA_NAME_PREFIX` / `TEST_DATA_EMAIL_DOMAIN`）。
  `scripts/create-test-member.mjs` と dryRun（`DRYRUN_PREFIX = ★DRYRUN_`）はこの印で作る。
- 手順は Skill `/dbops`「テストデータを作る場合」、運用は `docs/04` §5.2.2。

## 2. 物理削除 — 手順

admin split のエディタで、MASTER だけが実行できる（`assertMasterOperator_`）。

```
previewTestDataPurge_LOG    対象・表ごとの件数・残るもの・止まる理由を出す。確認した内容を 30 分記録する
executeTestDataPurge_APPLY  確認から 30 分以内・確認した人と同じ・内容が同じときだけ消す
```

- 実行時に計画を作り直し、確認時の指紋（対象 ID と件数の SHA-256）と比べる。違えば止まる。
- 消したあと同じ判定で数え直し、残りの行数を返す（0 であるべき）。
- 監査ログに `TEST_DATA_PURGE`（実行者・対象 ID・表ごとの件数。名前は残さない）を 1 行残す。
- 本番 DB の不可逆操作。AI が実行するときは毎回 operator の承認を取る（AGENTS.md L0.3）。

## 3. 設計 — ゴミを残さないための確認

会員・職員・外部申込者の ID が書き込まれうる場所をすべて洗い出し、扱いを決めた。
**表ごとの扱いは `TEST_DATA_PURGE_TABLE_POLICY` が正本で、テーブル定義の全 28 表を分類している。**
表を足して分類を忘れると `test:test-data-purge` が落ちる。

| 扱い | 表・場所 | 消す条件 |
|---|---|---|
| CASCADE | 会員・職員・認証アカウント・管理者リスト・研修申込・年会費 2 表・役員・振込口座・支払い・支払い明細・請求・変更申請（13 表） | 既存の削除と同じ連動 `getCascadeMatchers_`。**本番の表と `*_archive` の両方** |
| ↑の追加 | 研修申込 | テストの外部申込者の申込 |
| ↑の追加 | 変更申請 | 承認前のテストの入会申込（会員 ID が無い） |
| PURGE | 外部申込者 | 印 |
| PURGE | ログイン履歴（ログ用 SS） | 消す認証アカウントのもの |
| PURGE | メール送信明細（ログ用 SS） | 受信者が消す会員・職員・外部申込者のもの |
| PURGE | 削除ログ | 対象がすべて消す会員・職員のもの（論理削除時のスナップショットに個人データを持つ） |
| PURGE | 人物統合ログ | 新旧の ID がすべて消す会員・職員のもの |
| Drive | 請求の添付 | 請求添付フォルダ内のファイルだけゴミ箱へ。フォルダ外には触れない |
| Script Properties | 旧 dryRun の記録 `DRYRUN_APPLICATION_MANIFEST_V1` | 残っていれば消す |
| KEEP | 監査ログ | 操作の記録。ID だけで個人データを持たない。物理削除そのものもここに残す |
| KEEP | メール送信ログ | 送信のまとまり（件数）だけ。宛先は明細側にある |
| KEEP | 実在の事業所の変更申請 | テスト職員の追加申請など。実在会員の記録なので消さず、確認時に件数を出す |
| NONE | 研修・設定・ロール・テンプレート・画面項目権限・規程・共有メモ・LINE 投稿依頼 | 会員と結び付かない |

**シートの空行**: 行を消したあと、空いた末尾の行もシートから削除する（`takeRowsByMatch_`）。
以前のアーカイブ移動は中身だけ消して空行を残しており、容量が減らなかった。この処理は
論理削除（アーカイブ移動）とログイン履歴の削除とも共有している。

**連動の範囲**

- テスト事業所の職員は、職員側に印が無くても事業所と一緒に消す。
- 実在の事業所に属するテスト職員は、職員だけを消す。

### 止まる条件（fail-closed）

| 条件 | 理由 |
|---|---|
| 申込中（`APPLIED`）のテストの研修申込がある | `T_研修.申込者数` がずれる。先に取り消す |
| 実在の事業所の代表者に印がある | 代表者は単独では消さない（論理削除と同じ） |

## 4. 置き換えたもの

後片付けが 3 系統あり、「テストデータとは何か」の定義が分かれていた。印に統一し、物理削除 1 つにした。

| 廃止 | 見分け方 | 消し方 |
|---|---|---|
| `deleteTestDataPreview_LOG` / `deleteTestData_APPLY` | `DRYRUN_` / `test-member-*.invalid` / 氏名に「テスト」 | 論理削除 |
| `previewStrictE2ETestMemberCleanup_LOG` / `executeStrictE2ETestMemberCleanup_APPLY` | `test-member-*.invalid` | 論理削除 |
| `previewDryRunApplicationCleanup` / `executeDryRunApplicationCleanup` / `inspectDryRunManifest_LOG` | dryRun が Script Properties に残した ID | 論理削除（**取りこぼしの不具合**・`docs/300` §6） |
| `scripts/run-e2e-test-cleanup.mjs` / `inventory-demo-data.mjs` / `cleanup-live-test-members.mjs` | 上記を呼ぶ自動化 | — |

補助関数 4 本（`_collectTestDataTargets_` ほか）もあわせて削除した。呼び出し関係を機械的に解析し、
廃止したツールからしか呼ばれない関数だけを消している。

あわせて、監査ログへの書き込みを `appendAuditLogEntries_` の 1 つに集約した（エクスポート・会員編集・
ロール・プレビュー・物理削除の 5 つの書き手が同じ 9 列を個別に組み立てていた）。

## 5. 対象外としたもの

- **印の無い過去のテストデータ**（アーカイブに残る、2026-10-02 以前に論理削除したテスト会員など）。
  ID 指定で消すと「印の 2 条件」という安全装置を迂回するので、今回は扱わない。
- **実在のアドレスで作ったテスト会員**（`create-test-member.mjs --contact-email`）。印がそろわないので対象外。
  作成時に警告を出す。手で片付ける。

## 6. 検査

`npm run test:test-data-purge`（13 件）。実ソースの関数を切り出し、本番の表・アーカイブ・ログ用 SS を模した
偽の DB で、確認 → 実行まで動かす。

- 印は両方そろったときだけ（★だけ・メールだけ・白い☆・事業所の姓に★、はすべて対象外）
- 全テーブルが分類され、CASCADE の分類が実際の連動と一致する
- 確認なし・30 分超過・別人・内容の変化で止まる
- **実行後、テストデータは 0 行、実データは 1 行も減らない**（13 表・アーカイブ・ログ・Drive）
- 空いた行がシートから消える／添付はフォルダ内だけ／申込中・実在代表者で止まる
