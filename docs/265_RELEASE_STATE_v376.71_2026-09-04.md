## 1. 直した問題

会員ログインは **5 回失敗で無期限ロック**だった。ログイン ID は介護支援専門員番号で、
**名簿を見れば分かる＝推測できる**。つまり第三者が誰かのアカウントを狙って 5 回失敗させれば、
その人を無期限に締め出せる状態だった（可用性への攻撃）。

## 2. 確定仕様と実装

| # | 項目 | 仕様 |
|---|---|---|
| 1 | カウント | **連続した**失敗のみ。**成功した時点で失敗回数・ロック・解除予定をすべてリセット** |
| 2 | 段階的な待機 | 3 回目 → 1 分 / 4 回目 → 5 分 / 5 回目 → 15 分 / 6 回目以降 → 60 分（上限） |
| 3 | 自動解除 | 解除予定を過ぎたら自動解除し、失敗回数も 0 に戻す |
| 4 | 恒久ロック | **連続 20 回**で管理者対応が必要な状態へ。成功すれば 0 に戻るので正当な利用者は到達しない |
| 5 | 管理者解除 | 資格情報の再発行でロックが完全に解除される（既存機能。解除予定日時もクリアするよう修正） |
| 6 | エラー文言 | **ロック中もパスワード不一致と同一文言**。ロック状態を攻撃者に教えない |
| 7 | 例外 | ロック中は正しいパスワードでも通さない（待ち時間の短縮を許さない） |
| 8 | ログ | 失敗・ロック・自動解除を `T_ログイン履歴` に記録（GAS では接続元 IP を取れないため記録しない） |

### 実装上のポイント

- 閾値は **`LOGIN_LOCKOUT_POLICY` の 1 か所**に集約した。
  **`failedCount >= 5` のベタ書きが 2 か所にあった**（会員ログインとパスワード変更）のを撤去（`AGENTS.md` §3）
- **v376.70 以前に無期限ロックされた行は、解除予定が空 → 解除対象**として扱う。
  移行前にロックされた会員を締め出したままにしない
- 解除予定の値が壊れていた場合も解除対象にする（**締め出す方向に倒さない**）
- 会員セルフサービスの principal 解決側にも時限解除を通した。
  「ログインは通るのに他の操作が弾かれる」状態を作らないため
- ログイン画面に案内文を追加。**ロック中かどうかは書かない**（#6 と矛盾させない）

### スキーマ変更
