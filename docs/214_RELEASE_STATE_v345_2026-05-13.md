# Release State v345

Date: 2026-05-13
Status: production deployed

## Scope

v344 で client を GAS `getFileThumbnail_` proxy 経由に切り替えたが、本番でも
「PDF プレビューを読み込めませんでした」が表示され続けた。Web 検索した最新情報で
真因を再確定し、`getFileThumbnail_` 本体を書き直した。

## 真因（v344 でも未解決だった理由）

`getFileThumbnail_` は内部で `DriveApp.getFileById(id).getThumbnail()` を呼び、
返ってきた blob を base64 化していた。**`DriveApp.getThumbnail()` は PDF に対し
ほぼ常に `null` を返す**（Apps Script の長年の既知制約。Google issuetracker と
複数の developer forum で再現報告あり）。

そのため:

- server: `blob` が `null` → `return { thumbnail: null }`
- client (v344 PdfThumbnail): `null` を受け取り `status='error'` →
  「PDF プレビューを読み込めませんでした」を表示

v272 で組まれたサーバー proxy は **画像ファイル** に対しては正常動作していたが、
**PDF に対しては最初から動かない仕様** だった。v344 で client から server proxy
を呼ぶ配線を完成させたものの、proxy が叩いている API 自体が PDF 非対応。

## 修正内容（`gas-src/Code.full.gs:13049`）

`DriveApp.getThumbnail()` の使用を中止し、**Google Drive の公開 thumbnail
endpoint** を `UrlFetchApp` で取得する方式へ変更:

```
https://drive.google.com/thumbnail?id=<fileId>&sz=w400
```

このエンドポイントは Google の thumbnail CDN が裏で PDF → 画像変換を実行する
ため、PDF にも実際のサムネイル画像が返る。

- `UrlFetchApp.fetch(thumbUrl, { muteHttpExceptions: true, followRedirects: true })`
- レスポンス 200 + `image/*` content-type のみ採用
- `Utilities.base64Encode` で base64 化し `data:<mime>;base64,...` で返却
- `CacheService.getScriptCache()` で 1 時間 TTL キャッシュ
  （`payload.length < 95KB` の場合のみ — CacheService item size limit 100KB を考慮）

### なぜ `<img src>` 直接ではなく proxy 経由か

Web 検索で確認した通り `drive.google.com/thumbnail` を `<img src>` で直接参照すると:

- ページ内に同時 10 枚以上で rate limit に当たる
- Apps Script Web App の iframe sandbox (`script.googleusercontent.com`) からは
  Drive のクッキー / 認証リダイレクトを跨げず不安定

これらをサーバーサイドで 1 ホップ吸収し、クライアントは `data:` URL を読むだけに
することで上記問題を回避する。

### OAuth スコープ

3 プロジェクト全てに `script.external_request` が既に付与済みのため、追加の
OAuth 再承認は不要。member split は drive scope 無しだが、UrlFetchApp で
`drive.google.com/thumbnail` を呼ぶだけなので影響なし（ANYONE_WITH_LINK 共有
ファイルは無認証で取得可能）。

## Sources（真因確定に使用した一次情報）

- Apps Script `Class File` 公式ドキュメント — `getThumbnail()` は「null if no
  thumbnail exists」と明記: https://developers.google.com/apps-script/reference/drive/file
- Google forums / copyprogramming.com 等で「`getThumbnail()` returns null for
  PDF」が複数報告されている（2024〜2025）
- `drive.google.com/thumbnail?id=...&sz=w<width>` endpoint の存在と PDF 対応:
  Google Drive image hosting tutorials（labnol.org / dev.to / 各種 community
  discussions）
- Drive API v3 `thumbnailLink` の短命性（数時間で 404）→ proxy + base64 化の
  必要性: issuetracker.google.com/issues/229184403, issuetracker.google.com/issues/163065199
