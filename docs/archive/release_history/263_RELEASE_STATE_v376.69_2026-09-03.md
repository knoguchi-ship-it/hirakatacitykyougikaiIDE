## 1. 背景

一括編集で直せるのは **6 項目**（メール／発送方法／郵送先／状態／入会日／退会日）だけで、
住所や電話をまとめて直すには**スプレッドシートを直接開く**しかなかった。
GCP 移行後はそれができなくなるため、移行を待たず対象を広げた（A の汎用エクスポートに続く 2 件目）。

## 2. 実装

### 追加した 14 項目（計 20 項目）

| 区分 | 項目 |
|---|---|
| 連絡先 | 勤務先電話 / FAX / 携帯 |
| 勤務先 | 事業所名 / 郵便番号 / 都道府県 / 市区町村 / 住所 / 建物名等 |
| 自宅 | 郵便番号 / 都道府県 / 市区町村 / 住所 / 建物名等 |

### UI

列数が増えすぎないよう**折りたたみ式**にした。ツールバーの「**連絡先・住所も編集する**」で
各行の下に入力欄が展開される。既定は従来どおりの表示。

### 対象外にしたもの（意図的）

| 対象外 | 理由 |
|---|---|
| **事業所職員の連絡先・住所** | `T_事業所職員` は電話・住所の**列そのものを持たない**（連絡先は所属事業所＝`T_会員` が正本）。保存先が無いものを許可リストに入れない。列を増やす場合はスキーマ変更が先 |
| 氏名・カナ | 本人特定に直結。一括で書き換えると事故が大きい |
| 介護支援専門員番号 | **会員マイページのログイン ID**。一括変更はログイン不能を招く |
| 会員種別・職員数上限 | 種別変更は専用の移行機能、上限は事業所設定で扱う |

> 実装中に一度、職員側の許可リストにも `phone` / `mobilePhone` を入れかけたが、
> テーブル定義を確認して**列が無い**ことが分かったため撤回した。
