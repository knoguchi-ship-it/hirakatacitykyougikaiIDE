# v376.100 リリース状態（2026-09-22）

## 1. 結論

事業所職員の介護支援専門員番号を変更したときに、ログインIDが追従するようにした。あわせて、変わったログインIDを職員本人と申請者（代表者）へメールで返す。

v376.99 の調査で、個人会員（介護支援専門員番号）・事業所会員（事業所番号）はログインIDを書き換えるのに、**事業所職員だけ追従していない**ことが判明していた。ログイン不能にはならないが、ログインIDと番号が一致しなくなる不整合だった。

## 2. 変更内容

### 2-1 ログインIDの同期

`syncStaffLoginIdToCmNumber_` を追加した。職員情報変更の承認で介護支援専門員番号が変わったとき、`generateCmBasedLoginId_` で採番し直して `T_認証アカウント` の `ログインID` を書き換える。

- **既存ログインIDとの重複を避ける。** 退会者の認証行はログインIDを保持したまま残るため、素朴に番号をそのまま入れると衝突する。v376.73 で実際に事故になった経路。
- 同じ番号なら書き換えない（無意味な更新と通知を出さない）。
- 削除済みの認証行は対象外。
- 同期に失敗しても業務処理は止めず、Chat の「要確認」へ回す。

### 2-2 通知

ログインIDが変わったら `LOGIN_ID_CHANGED`（v376.99 で新設した設定可能な文面）で通知する。

**宛先は職員本人と申請者（代表者）の両方。** 本人は実際にログインする側、代表者は申請した側として結果を知る必要がある。同じ宛先なら二重には送らない。職員のメールアドレス変更も同時に申請されている場合は、新しいアドレスへ送る。

### 2-3 既存データは触らない

すでに介護支援専門員番号とログインIDがずれている職員がいても、**そのままにする**。一括で書き換えると、現に使われているログインIDを奪うことになるため（operator 判断）。本リリースの同期は「これから変えたとき」にだけ効く。

## 6. 運用上の申し送り

1. **実データでの動作確認が未了。** 職員の介護支援専門員番号を変更する変更申請を出して承認し、`T_認証アカウント` のログインIDが追従すること、職員本人と代表者へメールが届くことを確認する。`scripts/verify-staff-flow.mjs update <事業所番号> <返信先メール> --submit` が使える。**認証情報に触れる変更なので、テスト事業所で行うこと。**
2. すでにずれている職員のログインIDは直していない（§2-3）。棚卸しが必要なら、本番で介護支援専門員番号とログインIDが不一致な職員を読み取り専用で数えるところから始める。
3. ログインIDは `9` ＋ 番号の形で採番される。重複時は採番規則に従って別の値になるため、**通知の「新ログインID」が番号と一致しないことがある**。通知は実際に書き込まれた値を送る。
