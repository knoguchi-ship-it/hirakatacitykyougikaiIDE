# v376.99 リリース状態（2026-09-22）

## 1. 結論

ログインIDが変わることを公開ポータルの画面で案内していたのをやめ、変わった事実を変わった後にメールで伝える方式へ改めた。会員マイページを会員へ展開していない現状では、画面に「ログインIDも変わります」と書いても受け手に行き場がなく、矛盾した案内になっていたため。

あわせて、固定文で送っていた通知を他のメールと同じく管理画面で編集できるようにし、設定キーはあるのに送信箇所が無かった「空回りのカード」2 枚を配線した。

## 2. 新設したメール種別

いずれも `src/shared/mailTemplates.ts` のカタログへ追加し、管理画面のカードから件名・本文・送信 ON/OFF を編集できる。

| 種別 | カード | 系統 | 送信タイミング | 差し込み |
|---|---|---|---|---|
| `LOGIN_ID_CHANGED` | ログインID変更のお知らせ（本人へ） | 認証・セキュリティ | 変更承認時。**ログインIDが実際に変わったときだけ** | 氏名 / 旧ログインID / 新ログインID |
| `CONTACT_EMAIL_CHANGED` | メールアドレス変更のお知らせ（旧・新の両方へ） | 会員手続き | 職員情報変更の承認時 | 氏名 / 旧・新メールアドレス / 宛先区分 |

`CONTACT_EMAIL_CHANGED` は、職員情報変更の承認処理に直書きされていた固定文を置き換えたもの。乗っ取り検知のため旧アドレスにも送る設計は維持し、`{{宛先区分}}` でどちら宛の案内かを出し分ける。

## 3. 空回りだったカードの配線

設定キーと管理画面のカードはあるのに送信箇所が無く、**文面を編集しても届かない**状態だった 2 枚を配線した。

| カード | 修正内容 |
|---|---|
| 会員情報変更確認メール | `MEMBER_UPDATE` の承認時に、設定の文面を描画して送る |
| 退会申請受付確認メール | 承認時に送る。退会予定日は承認時にしか確定しないため受付時では空になる |

退会の既定文面は「退会予定日: {{退会予定日}}**（年度末）**」と直書きしており、v376.92 で入った即時退会でも「年度末」と書かれてしまう状態だった。`{{退会方式}}` の差し込みへ変更した。

## 4. 公開ポータルの変更

介護支援専門員番号と事業所番号の変更項目から「⚠ 変更するとログインIDも変わります」を削除した。

## 5. ログインIDの挙動（調査結果）

| 変更対象 | ログインID |
|---|---|
| 個人会員の介護支援専門員番号 | 変わる（`T_認証アカウント` の `ログインID` 列を書き換え） |
| 事業所会員の事業所番号 | 変わる（同上） |
| **事業所職員の介護支援専門員番号** | **変わらない**（書き換え処理が存在しない） |

職員のケースは個人・事業所と挙動が異なるが、**ログイン不能にはならない**。ログインは `T_認証アカウント` の `ログインID` 列で引き（`memberLogin_`）、職員とは `職員ID` 列で結ぶため、介護支援専門員番号を経由しない。ログインIDは発行時に `generateCmBasedLoginId_` で採番したスナップショットである。

`generateCmBasedLoginId_` は v376.73 で、退会者の認証行がログインIDを保持したまま残ることによる重複を避けるために導入された。職員のログインIDが追従しないことは、その観点では安全側に働く。

**揃えるかどうかは operator 判断。** 認証に関わるため本リリースでは変更していない。

## 8. GCP 移植メモ

新設 2 種別も既存と同じ「設定キー 3 つ（ENABLED / SUBJECT / BODY）＋ `renderConfiguredMail_` で描画」という形に揃えている。移植時はカタログ `src/shared/mailTemplates.ts` をそのまま持ち込み、送信箇所が種別ごとに 1 つであることを保つ。種別を足して送信箇所を作り忘れると、今回直した「空回りのカード」が再発する。

## 9. 運用上の申し送り

1. 既定文面のまま運用する場合、`T_システム設定` に行が無ければ既定値が使われる。文面を変えたい場合だけ管理画面で編集する。
2. 事業所職員の介護支援専門員番号変更ではログインIDが変わらないため、`LOGIN_ID_CHANGED` は送られない（§5）。
3. 一括メール送信画面の差し込みには、v376.98 の挿入 UI を適用していない。
