## 2. 作業中の事故（記録として残す）

最初に書いた削除スクリプトが**スライス合成を誤り**、`gas-src` に
**10,047 行を重複挿入**してファイルを壊した。`git checkout` で復元し実害は無い。

原因は 2 つ。

1. 削除範囲の計算に**括弧の数え上げ**を使った。`{{会員種別}}` のような文字列リテラルを
   含む関数（`dryRunMailMergeTagsV376_66_LOG`）で終端を見失った
2. 複数箇所を**文字列スライスの合成**で削ったため、範囲が重なると内容が複製された

作り直した版は次の手順にした。

1. 行範囲を**先に全部確定**する（終端は「次の top-level 宣言の直前」。括弧は数えない）
2. **重なりが無いこと**を検査する
3. **後ろから**削る
4. 削除後に**行数と関数数を検算**してから書き出す
5. `--apply` を付けない限り**書き込まない**

`HANDOVER.md` §4 の落とし穴にも追記した。

## 3. 文書の ID 整合検査（SOW §8 U-22 の解消）

SOW §1.2 の成功条件「文書間の重複を機械検査で 0 件にする」は、v376.73 の整合確認の時点で
**検査自体が存在しない**ことが判明していた。

### 縮小版で実装した理由

当初構想の「**文面の重複そのものを検出する**」は、重複の機械判定が曖昧で誤検出が多く、
運用の邪魔になると判断した（operator 合意）。代わりに **ID の整合**を突き合わせる。
誤検出がほぼ無く、**実際に起きた事故**（v376.73 で「実装済みなのに未実装と書いてある」を
4 件見逃した）を捕まえられる。

### 検査するもの

```
npm run test:docs-single-source
```

1. 5 文書が参照する `U-xx` が **SOW §8 に実在するか**（幽霊参照を作らない）
2. `U-xx` の重複（欠番は警告に留める。ID は再利用しない方針のため）
3. 要件 ID（`NF` / `BR` / `MG` / `SCR` / `TM`）の重複と、**正本以外の文書での定義**
4. 要件 ID が**トレーサビリティ一覧**（`docs/268`）から辿れるか（`BR-01〜04` の範囲表記も展開して照合）
5. **解決済みの未確定事項**が、他文書で「未確定 / 未実装 / 判断待ち / 検討中」のまま残っていないか

**検査しないもの**: 文面そのものの重複。人手の整合確認（`docs/267` §4）に委ねる。

### 4.1 responsive テストが v376.74 以降ずっと失敗していた（今回発見・修正）

テストレポートを再生成したところ、**公開ポータルの responsive が FAIL** だった。

原因は `scripts/responsive-test.mjs` の更新漏れ。v376.74 で重要事項ダイアログを廃止し
内容をステップへ移したのに、テストは**廃止済みのモーダル起動ボタン**を探し続けており、
7 ビューポートすべてで `モーダル起動ボタンが見つかりません` を記録していた。

**より問題なのは、その間ずっと「PASS」と報告していたこと。**
`HANDOVER.md` §4 の「responsive の合否は `result.json` を見る」に従って
`fatal` と `consoleErrors` は確認していたが、**`views[].error` を見ていなかった**。
`scripts/build-test-report.mjs` の判定はこれも数えるため、レポートだけが FAIL を示していた。

**修正**: `noticeDialog` ビューを廃止し、**`noticeStep`（種別選択後の注意事項ステップ）**に置き換えた。
共通の注意事項が出ること・種別ごとの折りたたみが初期は閉じていること・確認チェックがあることを
各ビューポートで計測する。修正後は 7 VP × 3 ビュー = 21 view すべて PASS。

**教訓**: 画面を作り替えたら、その画面を見ている E2E も同じターンで直す。
合否は自分の基準ではなく、**`build-test-report.mjs` の判定**（`fatal` / `views[].error` /
横スクロール / タップターゲット / `consoleErrors`）で見る。
