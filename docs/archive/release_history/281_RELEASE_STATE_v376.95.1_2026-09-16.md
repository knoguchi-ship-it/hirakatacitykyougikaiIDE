# v376.95.1 リリース状態（2026-09-16）

## 1. 結論

管理画面の通知設定を「メール通知」と「Google Chat」に分離した。メールの全体制御は、停止／通常送信／テスト集約の一つの配信状態に統合し、重複していた全体停止・送信抑止・配信モードの画面操作を廃止した。

会員手続きの Google Chat 通知は、申請IDをキーに受付と処理完了を同じスレッドへ投稿する。Webhook 接続情報は引き続き実行環境の秘密設定だけで管理し、管理画面・DB・ログには出さない。

## 2. 実装内容

- メール配信状態を `STOPPED`／`LIVE`／`REDIRECT` に正本化し、旧 `MAIL_GLOBAL_ENABLED`／`MAIL_DELIVERY_MODE` はロールバック互換のためだけに同期保持する。
- 既存環境は、正本キーが未保存または初回追加時に旧キーと矛盾した場合、旧設定を読み替えて従来の配信状態を維持する。新設定画面を保存すると正本キーと旧互換キーが同期される。
- `メール通知` には配信状態とメール種別・本文だけを表示する。
- `Google Chat` には受付・処理完了・要確認の有効化と本文だけを表示する。接続設定や Webhook 入力欄は置かない。
- 受付・処理完了の Chat 通知に同じ決定的 `threadKey` を付与し、同じ申請IDのスレッドへ集約する。
- 本番確認用の設定閲覧ハーネスは、設定値・本文・宛先をログへ出さず、表示構造だけを検査するよう安全化した。

## 5. GCP 移植メモ

Cloud Run のメール通知アダプタにも、同じ三値の配信状態と旧設定読み替え期間を設ける。Chat は Cloud Run の通知アダプタと Secret Manager を使い、Firestore に接続先を保存せず、申請ID由来の `threadKey` を実行時に導出する。

## 6. 運用上の申し送り

初回の v376.95 には、既存の通常送信設定を停止として解釈し得る初期値が含まれていたため、同一作業内で v376.95.1 へ切り替えた。現行の本番画面は既存の通常送信を正しく読み戻している。

切替までに発生した自動メールがあれば抑止された可能性がある。必要時だけ送信ログを読み取り専用で確認し、再送は operator 判断なしに行わない。今回のリリースでは、入会・変更・退会の実通知送信テストは実施していない。
