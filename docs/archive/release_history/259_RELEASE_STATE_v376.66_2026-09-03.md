## 1. 事象（operator 報告・2026-09-03）

事業所会員の新規申込を承認した後に送られるメールで、本文が次のようになっていた。

```
平井 ○○様の会員種別は{{会員種別}}となります。
その為、年会費は{{年会費}}となります。
```

**個人会員では正常**に「個人会員」「3,000円」と表示されていた。

## 2. 根本原因

**入会承認メールの送信経路が会員種別で 2 本に分かれており、事業所側にだけ差し込み変数が渡っていなかった。**

| 会員種別 | 送信関数 | `{{会員種別}}` / `{{年会費}}` |
|---|---|---|
| 個人・賛助 | `sendCredentialEmail_` | **置換する**（`opts.memberTypeLabel` / `opts.annualFee`） |
| **事業所** | `renderBizEmailTemplate_(template, bizVars)` | **渡していない → 素通り** |

- `renderBizEmailTemplate_` は「**渡された key だけ**」を `{{key}}` として置換する実装。知らないタグは原文のまま返す。
- 事業所の `bizVars` は `氏名 / ログインID / パスワード / 会員マイページURL / 事業所名` の 5 つだけだった。
- 承認処理はその直前で `M_会員種別` から `memberTypeLabelForEmail` / `annualFeeForEmail` を**すでに取得済み**で、
  個人向けの `credEmailOpts` にだけ載せて事業所側へ渡し忘れていた（取りこぼし）。

### 併発していた構造的な問題

1. **管理画面の差し込みタグ案内と送信側の実装が食い違っていた**。事業所カードは 5 タグしか案内しておらず、
   事務局が個人向けの本文をそのまま事業所テンプレートへ貼れてしまう状態だった。
2. **未解決タグがそのまま送信されていた**。どのテンプレートでもタグを打ち間違えれば生の `{{...}}` が会員へ届く。
   これはタグ名の増減が起きるたびに再発しうる**クラスの欠陥**だった。

## 3. 修正

| # | 内容 |
|---|---|
| 1 | **事業所メールに `会員種別` / `年会費` を渡す**（`bizVars` に追加）。代表者向け・メンバー向けの両方に効く |
| 2 | **年会費の整形を共通関数 `formatAnnualFeeForMail_` に集約**（`3000` → `3,000円`）。個人経路のインライン実装を DRY 化し、両経路の表記を揃えた。0・未設定・不正値は空文字（「0円」と誤送しない） |
| 3 | **未解決タグの流出防止（最後の砦）**: 全メール共通の出口 `deliverMail_` で、残った `{{...}}` を送信直前に除去し、`[mail/unresolved-merge-tag] category=... part=... tags=...` をログに残す（本文・宛先は出さない＝AGENTS §0） |
| 4 | **管理画面のタグ案内を送信側と一致**させた（事業所カードに `{{会員種別}}` `{{年会費}}` を追加） |

  GmailApp から Gmail API / 外部メール API に変わっても位置は同じ）。
- NG パターンには該当しない（シート数式・Drive 固有機能・Apps Script 固有 UI のいずれも使っていない）。
