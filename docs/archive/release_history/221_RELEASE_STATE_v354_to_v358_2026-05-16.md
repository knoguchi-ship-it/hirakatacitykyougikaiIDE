# Release State v354 → v358（案内 PDF プレビュー UX 確立まで）

Date: 2026-05-16
Status: production deployed (v358 現行)

## 経緯

v350 まで案内 PDF サムネイルのサーバ生成 pipeline は安定したが、ユーザーは
「サムネイルでは文字が読めない」「PDF の内容が読めるようにしたい」と要望。
ここから「lightbox 内で PDF を読める形にする」試行を v355 から v358 まで
4 サイクル繰り返し、構造的な制約を 1 つずつ消した上で **高解像度 PNG モーダル**
に着地した。

## なぜ「lightbox 内で全ページ閲覧」が構造的に不可能なのか（蓄積知見）

| 方式 | 障壁（2026 時点） |
|---|---|
| Drive `/preview` iframe | Drive レスポンスヘッダ `Content-Security-Policy: frame-ancestors https://drive.google.com` → 外部からの埋め込み拒否 (2024 以降の強化) |
| Drive `/uc?export=view` 直接 img | 2023 以降 hotlink 制限で 403 |
| blob URL iframe | Chrome が cross-origin (null-origin sandboxed iframe → blob) ナビゲーションを内蔵 PDF viewer に渡さない |
| data URL iframe | Chrome の data URL サイズ制限 約 2MB（5MB PDF は無理） |
| pdfjs-dist bundle | `pdfjs-dist/build/pdf.mjs` の Node 専用 dead code に `import.meta` が含まれ、`vite-plugin-singlefile` が plain `<script>` で出力するため SyntaxError |

## v358 採用（高解像度 PNG モーダル）

```
[サムネクリック]
  ↓ <PdfPreviewModal open=true fileUrl=... fetchHighResImage=callback />
  ↓ useEffect: fetchHighResImage(fileUrl) を呼び出す
  ↓ caller の実装は境界ごとに違う:
     - member / admin: (url) => api.getFileThumbnail(url, 2000)
     - public: (url) => callApi('getFileThumbnail', { fileUrl, size: 2000 }).then(r => r.thumbnail)
  ↓ server `getFileThumbnail_({ fileUrl, size })`:
     - size > 0 のとき Drive REST `files/<id>?fields=thumbnailLink` を Bearer 付きで取得
     - thumbnailLink (= lh3.googleusercontent.com/...) の `=s###` or `=w###` を `=w<size>` に置換
     - 取得した PNG を base64 化、`data:image/...;base64,...` で返却
     - CacheService キーは size 別 (`thumb_v358_<id>_s<size>`)
  ↓ client: `<img src={dataUrl}>` を中央表示
  ↓ Footer に「1 ページ目のみ」「全ページは別タブで」案内
  ↓ Header に「全ページを別タブで開く」(Drive viewer に飛ぶ)
```

### 強化点

- **`extractDriveFileId_` 共通ヘルパー**: `/file/d/`, `/d/`, `?id=`, `&id=`, 単体 fileId、URL encode 変形すべて対応。`getFileBytes_` / `trashFileFromUrlIfPossible_` も共用。
- **モバイル分岐廃止**: v357 では iOS Safari の blob URL iframe 制限のために UA 判定していたが、`<img>` 表示には不要なので削除。
- **CacheService**: 高解像度 PNG は 100KB 上限を超えるためキャッシュ skip。サーバ→クライアント間で毎回 ~1-2 秒のレイテンシ。許容範囲。

## Operator one-time setup（v350 から継承、未実施なら必須）

Apps Script editor で admin split プロジェクトを開き、関数選択
**`setupPendingThumbnailsTrigger`** を Run。10 分毎の `processPendingThumbnails`
trigger を登録する。これで大きい PDF / 旧 deployer 所有でない PDF の thumbnail
が後追いで backfill される。

## 既存研修のサムネイル backfill

`regenerateAllThumbnails` (clasp run 専用、project-scoped OAuth 必要) または
admin 編集モーダル内の **「サムネイル再生成」ボタン** (v350) で対応。失敗
ケース (旧 deployer 所有 PDF) は **admin 画面で PDF を再アップロード** すれば
v349 pipeline で即時生成される。
