# v360 リリース状態 — 研修名簿・出欠・一括メール明細

更新日: 2026-05-16
ステータス: **v361 として本番コード反映済み・operator 確認待ち**（admin split での schema migration 実行 + 実ブラウザ確認が必要）

スキーマバージョン: `2026-05-16-training-roster-v360`

## 1. 変更概要

研修管理に「名簿」コンソールを新設し、研修ごとの申込者一覧・出欠記録・手動追加・ゲスト枠・CSV 出力・集計・セグメントメール送信・送達ログ明細を統合した。

### 1.1 追加機能（UI）

| 機能 | 配置 | コンポーネント |
|---|---|---|
| 研修名簿タブ（閲覧・検索・フィルタ） | TrainingManagement > 名簿 / 出欠 | `src/components/TrainingRoster.tsx` 新規 |
| 出欠行内チェックイン（即時保存） | 名簿テーブル各行 | 同上 |
| 全員出席 / 全員欠席 一括セット | 名簿フィルタバー | 同上 |
| 会員 / 事業所職員の手動追加 | 名簿ヘッダー | `MemberAddDialog`（簡易: ID 直接入力）|
| ゲスト（非会員）追加 | 名簿ヘッダー | `GuestAddDialog` |
| 申込のキャンセル | 名簿テーブル各行 | 同上 |
| 事務局メモ編集（管理者専用） | 名簿テーブル各行 | 同上 |
| 集計カード（残席・区分内訳・出欠率） | 名簿上部 | 同上 |
| 事業所別申込数（折りたたみ） | 名簿上部 | 同上 |
| CSV (UTF-8 BOM) 出力 | 名簿ヘッダー | `src/lib/xlsx.ts`（CSV helper）|

### 1.2 追加機能（バックエンド）

新規 admin-only API action 11 件（`gas-src/Code.full.gs`）:

- `getTrainingRosterDetail` — 出欠・メモ・申込者種別を含む拡張版一覧
- `saveAttendance` / `saveAttendanceBatch` — 出欠記録（個別 / 一括）
- `addRosterEntry` — 会員 / 事業所職員の手動追加
- `addGuestRosterEntry` — ゲスト追加（T_外部申込者 + T_研修申込 同時作成）
- `cancelRosterEntry` — 管理者によるキャンセル（取消日時記録）
- `updateRosterEntry` — 事務局メモ編集
- `getTrainingStats` — 集計指標（残席・区分内訳・出欠率・事業所別）
- `getMemberTrainingHistory` — 会員ごとの受講履歴
- `sendTrainingMailSegmented` — セグメント絞り込み一括メール + 明細ログ
- `getTrainingMailSendLogs` — 送信ログヘッダー＋明細

## 2. DB スキーマ変更

### 2.1 新規マスタ: `M_出欠状態`

5 件のコード（UNRECORDED / PRESENT / ABSENT / LATE / SAMEDAY_CANCEL）。

### 2.2 T_研修申込 列追加（末尾 5 列）

`外部申込者ID`, `出欠状態コード`, `出欠記録日時`, `出欠記録者メール`, `事務局メモ`

### 2.3 T_メール送信ログ 列追加

`研修ID`（nullable, 研修関連送信時のみ）+ 新値 `送信種別=TRAINING_BULK`

### 2.4 新規テーブル: `T_メール送信明細`（ログ SS）

Header-Detail パターン。`T_メール送信ログ` をヘッダーとして per-recipient detail を分離。

### 2.5 ROSTER_TEMPLATE_LIST JSON 拡張

各エントリに `category` フィールド追加。欠落時は `MAILING_LIST` 既定値で auto-migrate。

詳細: `docs/03_DATA_MODEL.md §11 v360 Addendum`、`docs/learning/14_data_model_v360_2026-05-16.html`。

## 3. データモデリング設計判断

データモデル設計は本番反映前に独立した分析・確認プロセスを経た。詳細は新規 HTML 設計書を参照:

- `docs/learning/14_data_model_v360_2026-05-16.html` — ER 図・設計判断記録・既存資産流用判断
- `docs/learning/15_system_overview_v360_2026-05-16.html` — 拡張版システム概要

主要設計判断:

1. **既存資産流用 3 件で新規テーブル削減**: T_外部申込者・T_メール送信ログ・ROSTER_TEMPLATE_LIST を流用し、テーブル新規作成を 2 件に抑えた。
2. **Header-Detail パターン**: T_メール送信ログ + T_メール送信明細 を T_支払い / T_支払い明細 と同設計に。
3. **2-FK XOR 化（部分実施）**: T_研修申込 に `外部申込者ID` を追加し、申込者識別を `会員ID / 職員ID / 外部申込者ID` の XOR に移行（legacy `申込者区分コード` / `申込者ID` は読み取りのみ後方互換、v361 以降で物理削除予定）。
4. **3NF 準拠 + Soft delete + Audit 列**: 既存ルール継承。
