# 業務ルールを変えるときの手順

`AGENTS.md` L3 の「仕様と実装がずれない」を、実際の段取りにしたもの。
**仕様書を書き換えるだけで終わらせない。**

## なぜ順序が要るか

2026-10-02 の監査で、`AGENTS.md` に書いてある規約のうち
**6 件が実装されていなかった**ことが分かった（`docs/294`）。
「入力検証は deny-by-default」「例外時は fail close」と書いてあるのに、
電話番号は検証されず、退会ガードは素通りしていた。

**ルールが足りなかったのではなく、守られているかを測る手段が無かった。**
だから仕様を書いたら、測る手段を同じターンで作る。

## 手順

### 1. 仕様書を書く — `docs/spec/02_RD.md`

- **ID は再利用しない。** 撤回した BR の番号を別の用途に使わない
- **値そのものを書かない。** 桁数・パターン・金額の正本はコード（取得元はデータ・IF §9）
- **「なぜ」を書く。** 根拠の無い条文は、半年後に誰も残すか消すか判断できない。
  棚卸し（`docs/297`）では **199 条文中 76% に根拠が無かった**
- 実装と食い違いを見つけたときは、**どちらを正とするか operator に確認する**。
  勝手にどちらかへ寄せない

> 撤回する場合も残骸を残さない。2026-10-08 に BR-02 の
> 「代表者情報を会員レコードへ自動同期」を撤回したときは、
> **撤回の理由と、同期しても読み手が 1 つも無いことを調べた結果**を本文に書いた。

### 2. 実行して確かめる検査を足す — `scripts/test-validation-matrix.mts`

**文字列照合で済ませない**（`AGENTS.md` L3.2）。
gas-src から関数本体を取り出し、Node 上で実行して入力 → 受理／拒否 を突き合わせる。

```ts
const v = verdict({ ...OK_INDIVIDUAL, mobilePhone: 'でんわばんごう' });
assert.equal(v.ok, false);
```

照合してよいのは**配置・配線**だけ（allowlist に入っている / 3 split すべてに定義が残っている）。
**判定の正しさを照合で代用しない。**

> 実例: `test:office-affiliation` は「フロントが `phone:''` を送ると**書いてある**」ことを
> 検査して緑を保ち続けたが、その空文字は承認側で捨てられており、
> 退職しても前職の電話が消えない不具合が本番に居続けた。

### 3. トレーサビリティへ登録する — `docs/268`

**忘れると `npm run test:docs-single-source` が落ちる。**
BR-20 を新設したとき、実際にここで止まった。ゲートが先に気づく。

### 4. 検証方法欄を埋める

`docs/spec/02_RD.md` の BR 一覧表に、どのコマンドで確かめるかを書く。

- **「未検証」と書いてよい。** ただし**空欄にしない**。
  何がなぜ検証できていないかを書き、完了報告にも残す（`AGENTS.md` L4.3）

### 5. 既存データを確かめる — 厳格化なら必須

**検証を厳しくする変更は、本番データを先にスキャンする**（`AGENTS.md` L3.3）。

```
新しい規則を既存の全行に当て、違反件数と該当行を数える
```

違反があるとき、**既存データを人質にしない**。とる手段は 3 つ。

| | |
|---|---|
| 値を変えるときだけ検証する | `validateMemberPayload_` の `opts.stored` |
| 保存前に正規化する | 郵便番号の `normalizePostalCode` など |
| 先にデータを直す | operator に依頼する |

選んだ理由を release state 文書に残す。

> 実例: 書式検証を無条件に入れていたら、郵便番号 `573 -1191` と事業所番号 `0` を持つ
> **稼働中の 2 会員が、無関係な項目すら直せなくなる**ところだった。

### 6. 改訂履歴に版を起こす

`docs/spec/02_RD.md` の冒頭の表へ 1 行。何を変えたかと、根拠文書（`docs/2XX`）を書く。

## 完了条件

```bash
npm run test:validation-matrix   # 新しいケースが通る
npm run test:docs-single-source  # トレーサビリティ登録の確認
npm run prerelease               # exit 0
```

実装を伴う場合は `/release` へ。
