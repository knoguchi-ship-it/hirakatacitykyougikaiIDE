# 担当交代時のレビュー（ClaudeCode ⇔ Codex）

**レビュー自体ではレビューと提案だけを行う。** 修正も依頼済みなら、関連範囲のレビュー後、その承認範囲内で修正へ進む。レビューだけの依頼では修正しない。

2026-11-14 operator 決定: 起動時のH10は未レビュー範囲の通知であり、説明・読み取り調査を止めない。既存物を変更する前に、対象と依存先をレビューする。全作業のレビューを明示依頼された場合は全範囲を確認する。変更0件かつ作業ツリーがクリーンなら通知しない。範囲不明なら変更前に特定する。

起動条件は hook と `AGENTS.md` の起動時確認が見る（ClaudeCode: `.claude/settings.json` の SessionStart、Codex: `.codex/hooks.json` の SessionStart。
本体 `.claude/hooks/guard-cross-agent-review.mjs`）。hook は前の担当・対象範囲（HEAD の範囲）・未コミットの変更の有無を渡す。

H10の未コミット変更の記録は件数だけで、当時の内容のスナップショットではない。固定されたGit範囲と現在の作業ツリーを別々に確認し、件数から確認済みと推定しない。

## 1. 対象をつかむ

```bash
git log --stat <範囲>           # hook が渡した範囲。範囲が不明なら hook の指示どおり日時で引く
git diff <範囲>
git status --short               # 未コミットの変更（前の担当が途中で終えた可能性）
```

あわせて `HANDOVER.md` の再開プラン（§0.0）を読み、前の担当が「何をしたと言っているか」と実物を突き合わせる。

## 2. 評価する（変更の関連範囲。全体レビュー依頼なら全体）

| 観点 | 見ること |
|---|---|
| 正しさ | 変更が目的どおりか。境界・失敗時（fail-closed）・権限をサーバーで強制しているか（`AGENTS.md` L0.4 の 5 視点） |
| 規約 | `AGENTS.md` の L0〜L3。資格情報・本番操作の承認・`clasp deploy` 禁止・単一情報源・DRY |
| 仕様書の追従 | 機能のコードの変更に対し `docs/spec/` が追いついているか（Skill `/spec-sync` の観点）。`Spec: 不要` の理由が妥当か |
| 検査 | 新しい判定に実行する検査があるか。直す前のコードで落ちることを確かめたか。手元で読むだけの検査を回して結果を書く（下記） |
| 文書 | HANDOVER・release-state・release-notes・計画書が実物と一致しているか。未検証が完了に混ざっていないか |
| 引き継ぎ | 前の担当の残作業・operator への依頼が漏れていないか |

読むだけの検査（**ファイルを書き換えないもの**）は実行してよい。例:

```bash
npm run typecheck
npm run test:spec-trailer
npm run test:guards
```

`npm run prerelease`・ビルド・`release:*`・`clasp`・DB に触れるものは実行しない（記録や生成物を書き換えるため）。

## 3. 報告する

**重要度別の箇条書き**で operator に返す。各項目に「どこ（ファイル:行・コミット）」「何が問題か」「提案」を 1〜2 行で。

```
## 担当交代レビュー（前の担当: Codex／範囲: abc1234..def5678・未コミット 0 件）

### 重大（本番事故・セキュリティ・データ破損につながる）
- …

### 高（誤動作・規約違反。次の作業の前に直すべき）
- …

### 中（品質・保守性・文書の食い違い）
- …

### 低・提案（任意の改善）
- …

### 良かった点（任意・1〜3 行）
### 確かめたこと（実行した検査と結果）／確かめられなかったこと
```

- 該当なしの重要度は「なし」と書く（省かない）。
- 推測と確認済みを分ける。確かめていないものは「未確認」と書く。
- 全未レビュー範囲を確認した場合だけ、報告直前に `node .claude/hooks/guard-cross-agent-review.mjs <claude|codex> --ack` を実行する。一部の関連範囲だけを確認した場合は確認した版・ファイル・結果を報告し、--ackは実行しない。通知・説明・調査・後回しでは未レビュー情報を消さない。
- 修正の依頼がなければ報告後に指示を待つ。修正も依頼済みなら、レビュー結果を踏まえて承認範囲内の作業を続ける。
